# 手机端界面改进方案（待评审，未实施）

> 2026-10-20 起草。本文件只定方向，经确认后再分阶段实施。
> 依据：阅读 `index.html`、`shell/shell.css`、`shell/app.js`、`shell/theme.css` 及各 `views/*.css` 的窄屏规则。尚未在真机上逐页截图，实施前会先补一轮现状截图作为对照。

## 一、结论

现在的手机版不是"手机 App"，而是**桌面三栏页面在窄屏下被逐条打补丁**的结果。问题不在某个颜色或间距，而在结构：没有手机自己的导航模型、页面层级和组件。继续在 `@media (max-width: 760px)` 里加规则只会越补越乱。

改进方向：**保留同一套视图注册表和后端接口，单独做一层手机外壳与手机组件**，按 App 的习惯（导航栏 + 底部标签栏 + 页面栈 + 底部弹层 + 列表单元）重建主要页面。现有手机端代码只当反例参考。

## 二、现状问题（反例清单）

### 1. 骨架是桌面的，手机只是"隐藏掉一部分"

- `.app` 仍是桌面网格，手机上靠 `body.mobile-chat` / `body.mobile-panel` 把聊天列或面板列 `display:none`，本质是"三栏藏两栏"。
- `shell.css` 里有两段互相覆盖的 `max-width: 760px`：前一段把侧栏缩成 60px 窄导航（2717 行起），后一段又把侧栏整个隐藏、改用底部标签栏（3300 行起）。前一段大量规则已成死代码，后续修改很容易改错地方。
- 各视图断点各自为政：900 / 760 / 720 / 620 / 520 / 420px 都有，没有统一的"手机 / 平板 / 桌面"档位。

### 2. 没有页面层级和返回逻辑

- 所有功能都是平铺的"一屏"，没有"列表 → 详情 → 编辑"这种逐层进入、逐层返回的页面栈。
- 详情、编辑多用居中弹窗（`.modal`）或页内展开，手机上弹窗既挤又难关。
- 笔记编辑跳到独立的 `editor.html`，进出是整页刷新，没有转场，也没有统一的返回位置。
- 系统返回手势 / 安卓返回键与应用内状态没有对齐（hash 只记录"哪个视图"，不记录"进到了第几层"）。

### 3. 字号靠 `!important` 一刀切，层级被压平

- 手机上把 `p, span, div, li, td, button…` 全部强制 `16px !important`，再逐个为日历格子、徽标、排队条、圆环读数开例外。`shell.css` 中 `!important` 达 40 处，全仓库还有约 150 处 10–11px 的辅助字号。
- 结果是"标题、正文、说明"几乎一样大，界面没有主次；同时每加一个新组件都要记得补例外。
- 正确做法是一套字号令牌（大标题 / 标题 / 正文 / 说明 / 标签），组件按语义取用，而不是全局覆盖。

### 4. 把开发信息直接给用户看

- 聊天页顶栏同时塞着推送通道圆点、"AI 未接入"徽标、"正在连接后端…"状态胶囊、收起面板按钮；页面标题是"AI 智学 · 测试窗口"。
- 这些是调试信息，在手机首屏占据最显眼的位置，用户却不知道该做什么。

### 5. 操作入口密集、形态是网页的

- 笔记工具栏一行放筛选、连接状态、随手拍、上传、新建，下一行放搜索、标签、排序；窄屏下只能 `flex-wrap` 折行或横向滚动。
- 聊天输入区：`+`、两行 textarea、文字"发送"按钮，下面还有一整行控件（联网、思考、权限、用量、绘图）。
- 交互仍以 hover 为主，手机上换成了从桌面移植的波纹动画；缺少按压态、滑动操作、长按菜单等触屏常见反馈（只有笔记图谱 / Canvas 加了长按）。

### 6. 底部标签栏"像"但不"是"

- 5 栏标签 + "更多"弹层，选中态是一块带底色的圆角矩形，标签 11px，阴影和毛玻璃叠在一起，整体更像网页按钮组。
- "更多"里是平铺的图标网格，常用功能和设置、调试入口混在一起。

## 三、设计原则

1. **手机优先的独立外壳**：手机用自己的骨架，不再从桌面骨架里减法。桌面布局本轮不动。
2. **一屏一件事**：每个页面只有一个主要操作；次要操作收进导航栏右侧菜单或底部弹层。
3. **层级可预期**：进入是"推入"新页面，返回回到原位置并保留滚动位置；系统返回手势同样有效。
4. **用令牌而不是覆盖**：颜色沿用 `theme.css` 的白天 / 夜间令牌，新增字号、间距、圆角、阴影、动效令牌；组件只引用令牌。
5. **触屏的反馈和尺寸**：点按目标 ≥ 44px，按下有即时反馈（不依赖 hover），尊重 `prefers-reduced-motion`，处理刘海和底部安全区。
6. **说人话**：界面上只出现用户需要知道的状态（例如"AI 暂不可用，去设置"），连接诊断、接口状态移到设置里的"诊断"页。
7. **约束不变**：零运行时依赖、原生 HTML/CSS/JS、不引入框架和构建工具；复用 `Modules.list()` 注册表和现有 `/api/v1` 接口，不另维护一套业务逻辑。

## 四、目标形态

### 4.1 外壳结构

```
┌──────────────────────────────┐  ← 安全区（状态栏）
│ ‹ 返回     页面标题     ⋯ / ＋ │  导航栏：左返回，中标题，右主操作或菜单
│ 大标题（一级页面，滚动后收起）  │
├──────────────────────────────┤
│                              │
│  内容区（唯一滚动容器）        │
│  分组列表 / 卡片 / 空状态      │
│                              │
├──────────────────────────────┤
│  今天   日历   AI   笔记   我的 │  标签栏：只在一级页面显示
└──────────────────────────────┘  ← 安全区（Home 指示条）
```

- 一级页面（标签栏上的 4–5 个）显示大标题和标签栏；二级及更深页面隐藏标签栏，导航栏显示返回。
- 页面栈用 History API 管理（`pushState` / `popstate`），刷新后能回到同一层；转场为右进左出，返回反向。
- 弹出的内容一律用**底部弹层**（操作菜单、筛选、表单、确认），不再用居中弹窗。

### 4.2 标签栏建议（需你确认）

| 位置 | 建议 | 说明 |
|---|---|---|
| 1 | 今天 | 新首页：今日课程 / 日程、未完成待办、番茄钟入口、最近通知 |
| 2 | 日历 | 日 / 周 / 月，合并课表 |
| 3 | AI | 对话；也可做成各页右下角的悬浮入口，见待确认项 |
| 4 | 笔记 | 列表 → 阅读 → 编辑 |
| 5 | 我的 | 账号、学堂 / 教务、同步、外观、设置、诊断；其余低频功能也收在这里 |

替代"更多"网格：低频功能放进"我的"的分组列表，或"今天"页的快捷入口。

### 4.3 组件库（`mobile/` 下新建，所有手机页面共用）

- 导航栏（含大标题收起）、标签栏、页面栈与转场
- 分组列表单元：图标 / 标题 / 副标题 / 右侧值 / 箭头 / 开关，支持左滑操作（删除、完成）
- 底部弹层：操作菜单、表单、筛选；支持下拉关闭
- 分段控件、搜索框（下拉出现）、标签选择
- 空状态、加载骨架、轻提示（Toast）、确认对话
- 悬浮主操作按钮（仅在确有单一主操作的页面使用）

### 4.4 视觉令牌

- 字号：大标题 28–32 / 标题 20 / 正文 16–17 / 次要 14–15 / 说明 12–13；行高统一。输入框保持 ≥ 16px，避免 iOS 聚焦放大。
- 间距 4 / 8 / 12 / 16 / 24；页面左右边距 16px。
- 圆角：列表分组 12、卡片 16、弹层 20。
- 层次靠背景色区分（页面底色 / 分组底色），少用边框和重阴影。
- 动效：转场 250–300ms，按压 100ms，减少动效时改为淡入淡出。

## 五、主要页面改法（示例）

- **对话**：顶栏只留标题和"新对话 / 历史"；连接状态只在出错时以横幅出现。输入区为单行自增高输入框 + 圆形发送按钮，联网 / 思考等开关收进 `+` 弹出的底部弹层。键盘弹出时输入区贴着键盘（`visualViewport`）。
- **日历**：顶部周条可左右滑动切换，下方当日时间线；月视图作为切换项。点日程进入详情页，新建用底部弹层表单。
- **待办**：分组列表（今天 / 以后 / 已完成），左滑完成或删除，点 `＋` 弹出快速添加。
- **笔记**：列表展示标题 + 摘要 + 1–2 个标签；搜索框下拉出现；筛选、排序进右上角菜单。点进全屏阅读，右上"编辑"进入编辑页，手机上编辑 / 预览为上下或分段切换，不做左右分栏。
- **我的 / 设置**：分组列表，开关、选择项按系统设置的习惯排列；诊断信息单独一页。

## 六、实施路径

| 阶段 | 内容 | 验收 |
|---|---|---|
| 0 | 现状截图（360 / 390 / 430 宽，白天 / 夜间）作为对照基线 | 截图归档 |
| 1 | 手机外壳：令牌、导航栏、标签栏、页面栈、底部弹层、列表组件；清理 `shell.css` 中旧的窄屏补丁 | 空壳可导航、返回手势正常、无横向溢出 |
| 2 | 对话 + 我的 / 设置 | 两页按新组件重建，旧手机规则删除 |

| 4 | 日历 + 今天 | 日 / 周 / 月可用，首页聚合信息正确 |
| 5 | 其余低频页面 | 未重建前用通用"二级页面"容器承载旧视图，保证可用 |

每一阶段结束都会给你截图确认后再进入下一阶段。

技术取舍：
- 判断手机与否沿用现有 `isMobile()` 断点（760px），手机外壳挂 `body.is-mobile`，桌面代码路径不受影响。
- 视图模块增加可选的手机渲染入口（例如 `mobile.render`）；没有提供时退回通用容器渲染旧视图，所以可以逐页替换，不需要一次性重写。
- 现有 `test/mobile-pwa.test.js` 中关于标签栏组成（`MOBILE_PRIMARY`）的断言会随方案调整，PWA、离线加密、二维码相关断言保持不变。

## 七、需要你确认

1. **风格基调**：偏 iOS（大标题、分组列表、毛玻璃标签栏），偏 Material 3（顶部应用栏、FAB、底部导航胶囊），还是做一套中性的自有风格？我建议偏 iOS 的结构 + 自有配色，学生用户 iPhone 占比较高，且这套结构在两个平台上都不违和。
2. **标签栏**：是否同意"今天 / 日历 / AI / 笔记 / 我的"？待办放进"今天"还是单独一栏？
3. **AI 对话的位置**：作为一个标签，还是改成各页可唤起的悬浮入口（主页面不再默认是聊天）？
4. **范围**：是否按上面的阶段推进，先做外壳 + 对话 + 设置给你看效果？
5. **桌面端**：本轮是否确认完全不动桌面布局？
