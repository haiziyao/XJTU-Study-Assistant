# 模块开发指南

> 本文面向**要往这个项目里加功能的人**。目标：**新增一个功能 = 新建一个目录 + 新建一个文件，
> 不需要修改任何框架代码，也不会和别人的改动冲突。**

---

## 0. 三十秒版本

```bash
# 后端：新建一个模块目录
app/src/modules/study/
    module.js          # ← 唯一入口（描述符），框架靠它发现你
    study-service.js   # 你的业务逻辑
    routes.js          # 你的路由
    README.md          # 你的接口契约

# 前端：新建一个视图文件
app/src/renderer/views/study.js     # 调 PCModules.register(...) 自我登记
app/src/renderer/views/study.css    # 你的样式（类名加 study- 前缀）

# 登记（仅两处单行追加）
app/src/renderer/index.html         # 加一行 <script> 和一行 <link>
app/test/study.test.js              # 你的测试（test/*.test.js 会被自动收录）
```

跑起来：

```bash
cd app
npm run start:server   # 后端
# 浏览器打开 http://127.0.0.1:3210/app
npm test               # 全部用例
```

就这么多 —— 后端**零登记**（目录扫描），前端只有两行。

## 1. 目录约定：哪些能改，哪些不能

```
app/src/
├── shared/      ← 跨模块共享的纯函数与令牌（改动需组内评审）
│   ├── constants.js    端口 / 前缀 / 错误码 / WS 消息类型
│   ├── time.js         22 个日期时刻纯函数
│   └── theme.js        设计令牌（配色、复杂度阈值）
│
├── core/        ← 框架层：通用能力，**组员不要改**
│   ├── http/           router.js · websocket.js · static.js
│   ├── store/          json-store.js
│   ├── commands/       command-service.js（指令分发）· nlp-rules.js（中文解析原子函数）
│   ├── module/         contract.js（模块契约）· registry.js（目录扫描）
│   ├── ai/ai-bridge.js AI provider 注册契约
│   ├── validate.js     通用校验（必填/长度/枚举/整数）
│   └── routes.js       框架级路由
│
├── modules/     ← ★ 业务层：一人一个目录，互不越界
│   ├── calendar/       日历与待办（含前端 views/calendar.js）
│   └── lms/            思源学堂
│
├── server/index.js      装配入口（只做装配，不含业务）
├── main/                Electron 薄壳
└── renderer/
    ├── index.html       入口，含资源清单
    ├── shell/           外壳：app.js · planned.js · message.js · settings.js · shell.css
    ├── kit/             公共积木：registry.js · util.js · labels.js · dom.js
    └── views/           ★ 一人一个 .js + .css
```

**铁律**

1. `src/modules/<别人>/` 与 `renderer/views/<别人>.js` **只读**，不要改。
2. 需要框架加能力（新错误码、新 WS 消息类型）→ 群里说一声，别自己顺手改。
3. 新代码一律放自己的目录/文件；`shell.css`、`shell/app.js`、`index.html` 只允许**追加**。

## 2. 后端模块：`module.js` 描述符

框架启动时扫描 `src/modules/*/module.js`，读取默认导出，按 `order` 排序后依次调用钩子。
**完整契约（含每个字段的语义）见 `src/core/module/contract.js` 顶部注释。**

### 2.1 最小可用模块

```js
// src/modules/study/module.js
import { StudyService } from './study-service.js';
import { registerStudyRoutes } from './routes.js';

export default {
  id: 'study',            // 必填。小写字母/数字/连字符
  title: '学情',           // 必填。展示名
  order: 40,              // 装配顺序，小者先（默认 100）

  collections: [          // 你要的数据集合，JsonStore 自动创建并挂到 store 上
    { name: 'studyRecords', file: 'study-records.json' },
  ],

  createServices({ store, broadcast }) {
    return { study: new StudyService({ store, broadcast }) };
  },

  registerRoutes(router, ctx) {
    registerStudyRoutes(router, { study: ctx.own.study, apiPrefix: ctx.apiPrefix });
  },
};
```

数据会自动落到 `app/data/study-records.json`，通过 `store.studyRecords`（或 `ctx.store.collection('studyRecords')`）访问，
并自动继承**原子写、逐条容错、损坏先备份**的保护。

### 2.2 全部钩子

| 钩子 | 时机 | 典型用途 |
| --- | --- | --- |
| `collections` | 装配数据层时 | 声明集合（名字全局唯一） |
| `createServices(ctx)` | 建服务时 | 返回 `{ 服务名: 实例 }`，会并入全局 `services` |
| `restore(ctx)` | `listen()` **之前**，async | 恢复登录态、预热缓存。**失败会被降级捕获**，不会拖垮启动 |
| `registerRoutes(router, ctx)` | 注册路由时 | 注册自己的 REST 接口 |
| `start(ctx)` | `listen()` 成功后 | 启动定时器、订阅 |
| `stop(ctx)` | `close()` 时（**逆序**） | 清理定时器 |
| `aiTools` | 请求 `/ai/capabilities` 时 | 暴露给 AI Agent 的工具清单，自动聚合 |

`ctx` 里有：`store` · `broadcast` · `services`（含已装配的其它模块服务） · `own`（你自己 `createServices` 的返回值） ·
`dataDir` · `options`（`createServer({ [你的id]: {...} })` 传进来的配置切片） · `module`。

### 2.3 路由命名约定

```js
// src/modules/study/routes.js
export function registerStudyRoutes(router, { study, apiPrefix }) {
  const P = `${apiPrefix}/study`;        // → /api/v1/study/...
  router.get(`${P}/records`, ({ query }) => ({ items: study.list(query) }));
  router.post(`${P}/records`, async ({ body }) => {
    const item = await study.create(body ?? {});
    return { __status: 201, item };       // 返回体里带 __status 可指定 HTTP 状态码
  });
}
```

特殊返回约定（由 `core/http/router.js` 支持）：

- `{ __status: 201, ... }` → 指定状态码（默认 200）
- `{ __raw: { contentType, body, status?, headers? } }` → 非 JSON 响应（`body` 可以是 Buffer，用于图片）
- 返回 `undefined` → 204

写操作后记得广播，前端会自动刷新当前视图：

```js
this.broadcast({ type: 'data_changed', payload: { module: 'study', target: 'studyRecord', action: 'create', id } });
```

### 2.4 对话指令（可选）

想让「中间对话框」也能操作你的数据，只需**登记两个东西**，框架会白送你
`/commands/parse`、`/commands/execute`、`/commands/run` 全套能力：

```js
createServices({ store, broadcast, services }) {
  const study = new StudyService({ store, broadcast });

  // ① 解析器：把中文变成「指令对象」（可选 —— 也可以只做 ②）
  services.commands.registerParser('study', new StudyCommandParser());

  // ② 处理器：把「指令对象」落到你的数据上
  services.commands.registerHandler('studyRecord', {
    async create(draft, options) {
      if (options.dryRun) return { dryRun: true, planned: { fields: draft.fields } };
      const item = await study.create(draft.fields);
      return { item, affected: [{ id: item.id, title: item.title }] };
    },
    query(draft) { const items = study.list(draft.filters ?? {}); return { items, count: items.length }; },
    async complete(draft) { /* ... */ },
  });

  return { study };
}
```

- 处理器键名 = `action`，可自由定义（`create` / `query` / `update` / `delete` / `complete` / `rollover` / 你自己的）。
- `options.dryRun === true` 时**不要写库**，只返回预览。
- 没实现某个 action 也没关系，调用时会返回「可用：…」的明确错误。
- 中文日期/时刻解析可直接复用 `core/commands/nlp-rules.js` 的 11 个函数，**不要重写**。

### 2.5 跨模块协作

- **写**别人的数据 → 调对方服务：`services.schedules.create(...)`（校验、广播、日志都不会被绕过）。
- **读**别人的数据 → 可直接访问集合：`store.schedules.all()`（代价是要接受对方字段约定）。
- 依赖谁，就把自己的 `order` 排在谁后面：

| 模块 | order | 依赖 |
| --- | --- | --- |
| `calendar` | 10 | — |
| `lms` | 20 | calendar（同步时写日程） |
| 你的 | ≥ 30 | 按需 |

> 顺序错了不会报错，但会**静默失效**（例如 lms 拿不到 `services.schedules` 时同步会全部失败）。
> 因此依赖别人时，请在自己的 `module.js` 顶部注释里写清楚。

### 2.6 私有文件（凭据等）

需要放非集合形态的文件（会话 Cookie、密钥），用 `ctx.dataDir` 自己管理权限，例如：
`new JsonFile(path.join(dataDir, 'your-session.json'), { mode: 0o600 })`。
**不要**塞进 JsonStore —— 集合是 0644 的业务数据，语义不同。

## 3. 前端模块：`PCModules.register`

前端是**无构建步骤的 classic script**。每个视图文件在被 `<script>` 加载时自我登记，
外壳（`shell/app.js`）据此生成左侧功能栏。

```js
// src/renderer/views/study.js
(function () {
  // kit/ 下的公共积木是全局可用的：
  //   PCUtil        日期/颜色/转义等纯函数
  //   mk / option / field / iconBtn / errorBox / emptyBox / statPill / placeholderView
  //   CATEGORY_LABEL / STATUS_LABEL / ACTION_LABEL / TARGET_LABEL / PRIORITY_LABEL

  const ui = { data: null, busy: false };

  async function load(mount) {
    ui.busy = true;
    try {
      ui.data = await PC.api('/study/records');   // PC.api 已统一处理 { ok:false } 抛错
    } catch (error) {
      mount.appendChild(errorBox(error));
    } finally {
      ui.busy = false;
    }
  }

  function render({ mount }) {
    mount.innerHTML = '';
    const box = mk('div', 'study-card');          // 类名加自己的前缀，别用通用的 .card
    box.appendChild(mk('div', 'study-title', '学情概览'));
    mount.appendChild(box);
    load(mount);
  }

  window.PCModules.register({
    id: 'study',      // 与后端模块 id 一致
    label: '学情',
    icon: '📈',
    order: 40,
    title: '学情',
    render,
  });
})();
```

`render(ctx)` 收到的 `ctx`：`{ mount, api, state, toast, refresh }`
（`mount` 是已清空的面板容器；`api` 等同 `PC.api`；`refresh()` 重渲染当前视图）。

**写操作后不用手动刷新**：后端广播 `data_changed`，外壳会防抖 150ms 自动重渲染当前视图。

### 3.0 往「设置」页加一块自己的配置

设置页（左栏底部那个）支持模块自带的配置区块，用同一套注册表登记即可，不需要改外壳：

```js
window.PCModules.registerSettingsSection({
  id: 'study.thresholds',     // 建议带模块前缀
  title: '学情',              // 区块标题
  order: 40,                  // 小者在前（默认 100）
  render({ mount, toast, refresh }) { /* 与视图 render 同一套写法 */ },
});
```

`settings.js` 会按 order 依次渲染成 `.card`；没有注册区块时设置页与以前完全一样。
日历模块的「日程 → 分类管理」就是这么挂上去的（`views/calendar.js`）。

### 3.1 复用公共组件与跨模块能力

```js
// 打开日历模块的新建/编辑弹层（不要直接 import 别人的文件）
window.PCModules.getService('editor')?.({ target: 'schedule', defaults: { date: '2030-05-01' } });

// 自己对外提供能力
window.PCModules.service('studyChart', drawChart);
```

### 3.2 样式

```css
/* src/renderer/views/study.css —— 类名一律加 study- 前缀 */
.study-card { background: var(--bg-surface); border-radius: var(--radius); }
```

可用的 CSS 变量（定义在 `shell/shell.css` 的 `:root`，运行时会被 `/meta/theme` 覆盖）：
`--bg-base` `--bg-surface` `--bg-elevated` `--bg-hover` `--fg` `--fg-2` `--fg-3` `--line`
`--blue` `--red` `--green` `--orange` `--purple` `--radius`。
**不要写死颜色**，否则换主题时会和其它视图不一致。

### 3.3 登记到 index.html

```html
<link rel="stylesheet" href="views/study.css" />
...
<script src="views/study.js"></script>
```

> 如果你做的是 `shell/planned.js` 里已占位的功能（学情 / 拍题 / 网课），
> 注册同名 id 会自动覆盖占位；顺手把 `planned.js` 里对应那一项删掉即可。

## 5. 常见错误

| 现象 | 原因 |
| --- | --- |
| 左栏没有我的功能 | `index.html` 漏了 `<script>`；或 `PCModules.register` 的 `render` 不是函数（会在控制台抛错） |
| 页面整页白屏 | 某个脚本有语法错误/顶层引用错误。跑 `npm test`，`test/renderer.test.js` 会直接报出是哪个文件 |
| 后端启动日志里「跳过 xxx：目录下没有 module.js」 | 模块目录缺入口文件，或文件名拼错 |
| `/api/v1/modules` 里没有我的模块 | `module.js` 没有默认导出，或 `id` 不合法（必须是 `^[a-z][a-z0-9-]*$`） |
| 我的服务是 `undefined` | 依赖的模块 `order` 比自己大（还没装配）。把自己的 `order` 调大 |
| 集合名冲突 / 未知集合 | 集合名全局唯一；跨模块要用别人的集合请直连 `store.<名字>`（读）或调对方服务（写） |
| 对话指令报「不支持的 target」 | 忘了 `services.commands.registerHandler(target, handler)` |
| 数据没落盘 | 集合必须在 `collections` 里声明，`JsonStore` 才会创建并持久化 |
