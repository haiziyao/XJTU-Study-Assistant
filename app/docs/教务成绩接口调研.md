# 教务（ehall / jwxt）成绩接口调研

> 真机实测记录。**本文件只写路径、字段名与结论，不含任何账号、口令、姓名、学号或真实成绩。**
> 复现方式：`node scripts/ehall-probe.js`（凭据从环境变量读，见脚本头部注释）。

调研日期：2026 年。上游随时可能改版，**改版时只需要改 `modules/academic/config.js`**。

---

## 0. 一句话结论

成绩接口 `/jwapp/sys/cjcx/modules/cjcx/xscjcx.do` **不能直接打** —— 会稳定返回 `403`。
必须先用 **`funauthapp/api/getAppConfig`** 做一次「应用授权握手」并刷新 `_WEU` 防伪
token，之后才返回 `200 {"code":"0","datas":{"xscjcx":{"rows":[…]}}}`。

**这一个是整份调研唯一真正难找的点**，其余都是常规。

---

## 1. 登录链路（已实测跑通）

统一身份认证走 **CAS OAuth2**，不是思源学堂那种「直接 302 到 `/cas/login`」的经典写法。
拿一个 **jwapp 业务 URL** 进去，会依次跳 4 跳后落到 CAS 登录页：

```
GET  https://ehall.xjtu.edu.cn/jwapp/sys/<app>/modules/<mod>/<action>.do
  302 → https://ehall.xjtu.edu.cn/amp-auth-adapter/login?service=<原 URL>
  302 → https://org.xjtu.edu.cn/openplatform/oauth/authorize?appId=1030&redirectUri=…
  302 → https://login.xjtu.edu.cn/cas/oauth2.0/authorize?response_type=code&client_id=1030&…
  302 → https://login.xjtu.edu.cn/cas/login?service=…%2Fcas%2Foauth2.0%2FcallbackAuthorize…
  200   登录页（含 <input name="execution"> 隐藏域）
```

登录成功后 cookie 落在 `.xjtu.edu.cn` 相关域上（`CASTGC` / `MOD_AMP_AUTH` / `route` /
`asessionid` / `_WEU` / `JSESSIONID`）。
`CasAuth`（`modules/lms/cas-auth.js`）那套状态机**可以直接复用**：支持任意入口 URL，
RSA 加密密码、MFA、图形验证码、重定向链都不用重写。

### ⚠️ 坑一：门户页不能当登录入口

`https://ehall.xjtu.edu.cn/new/index.html?browser=no` 是**纯静态 SPA 外壳**：

| 指标 | 实测值 |
| --- | --- |
| 状态码 / 跳转次数 | `200` / `0`（**未登录时也是这样**） |
| 页面里有没有 `execution` | **没有** |
| `<title>` | 本科教务系统 |

`CasAuth.begin()` 的判定是「没有 `execution` 且最终 URL 不含 `/cas/login` ⇒ 已登录」，
于是它会**误判成「已登录」并跳过登录步骤**，后续业务请求再被 302 踢回 CAS。
**结论：`config.loginUrl` 必须指向 jwapp 业务 URL，不能指向门户页。**

### ⚠️ 坑二：两个主机

| 主机 | 角色 |
| --- | --- |
| `ehall.xjtu.edu.cn` | 一站式服务大厅：门户、应用中心、`/jsonp/*` 元数据、jwapp 模块接口 |
| `jwxt.xjtu.edu.cn` | 应用外壳里 `_JW_INIT_CONFIG.indexLogoUrl` 指向它；**需先 GET 建立会话，否则 401** |

成绩与课表的模块接口在 `ehall` 上就能打通，本模块只用 `ehall` 即可。

## 2. ★ 应用授权握手（关键，缺了必然 403）

顺序固定，四步：

```
1) GET  /jwapp/sys/cjcx/*default/index.do
        → 建立 jwapp 子系统会话；从页面里取 appId
          正则：/"appId"\s*:\s*"(\d+)"/   → 4768574631264620

2) GET  /jwapp/sys/funauthapp/api/getAppConfig/cjcx-<appId>.do
        → ★ 授权握手。返回该应用对本账号的模块声明：
          {"APP_ID":"…","MODULES":[{"route":"cjcx","title":"成绩查询","range":"1"}],"schoolID":"10698",…}
          少了这一步，后面必然 403。

3) POST /jwapp/sys/jwpubapp/modules/bb/cxjwggbbdqx.do
        body: SFQY=1&APP=<appId>
        → 刷新 `_WEU` 防伪 cookie（实测该 cookie 的值会变化）

4) POST /jwapp/sys/cjcx/modules/cjcx/xscjcx.do
        body: XNXQDM=*        （* = 全部学期）
        → 200 {"code":"0","datas":{"xscjcx":{"totalSize":19,"pageSize":999,"rows":[…]}}}
```

> 这条链路由本地参考实现 `D:\Code\个人教务系统\app.py` 的 `fetch_grades()` 给出，
> 其注释即「**支撑接口：刷新 _WEU（防伪 token），缺少会 403**」。
> 本项目的 `scripts/ehall-probe.js` 已逐跳复现并验证。

**只做第 4 步（哪怕 cookie、Referer、请求头、动作名全都对）一定 403** —— 这是本次排查
花费最多时间的一点。40 余次请求、8 个假设（登录态 / 动作名 / 请求形态 / cookie 作用域 /
浏览器请求头 / 登录入口 / 打开服务握手 / User-Agent）全部排除后，靠参考实现才定位到。

## 3. 模块接口通用形态

```
POST /jwapp/sys/<appName>/modules/<moduleName>/<action>.do
Content-Type: application/x-www-form-urlencoded; charset=UTF-8
Referer:      <host>/jwapp/sys/<appName>/*default/index.do
X-Requested-With: XMLHttpRequest
```

响应外壳：`{ "code": "0", "datas": { "<key>": { "rows": [ … ] } } }`
**`code` 是字符串 `"0"`，不是数字 0**（用 `=== 0` 判断会全部失败）。

### 错误形态对照（实测）

| 现象 | 含义 |
| --- | --- |
| `200` + `{"code":"0",…}` | 成功 |
| `200` + `{"code":"404"}` | 应用可访问，但**动作名不存在** |
| `200` + `{"success":false,"errMsg":"异常"}` | 应用可访问，参数不对（`emapcomponent` 的形态） |
| **`403` + Resin 错误页（`text/html`）** | **应用未完成授权握手**（不是路径错，也不是没权限） |
| `401` | 该主机会话未建立 |
| `302 → /cas/login` | 登录态失效 |

判定要点：**`403` 在 `cjcx` 上意味着"忘了握手"，不是"没权限"** —— 早期把它读成
「账号未授权」是错的，`funauthapp/qxgl.do` 那条申请入口与本问题无关。

## 4. 成绩数据字段表（`datas.xscjcx.rows[]`，实测）

只列与成绩/学分绩有关的字段；`*_DISPLAY` 是给界面看的中文值，原始值是无 `_DISPLAY` 的那个。

| 字段 | 类型 | 含义 | 备注 |
| --- | --- | --- | --- |
| `KCM` | string | **课程名称** | 必用 |
| `KCH` | string(10) | 课程号 | 幂等键候选 |
| `XF` | number | **学分** | 必用 |
| **`XFJD`** | number | **学分绩点** | ★ 学校直接给出，直接用于学分绩，**不需要自己换算** |
| `ZCJ` | number | **总评成绩** | 数值分（加权平均分用它） |
| `QMCJ` / `QMCJ_DISPLAY` | string | 期末成绩 | 可能是文本（等级制） |
| `QZCJ` | number/null | 期中成绩 | 可能为空 |
| `PSCJ` | number/null | 平时成绩 | 可能为空 |
| `XNXQDM` | string(11) | **学期代码** | 形如 `2025-2026-1` |
| `XNXQDM_DISPLAY` | string | 学期显示名 | 给界面用 |
| `KCXZDM` / `KCXZDM_DISPLAY` | string | **课程性质** | `必修` / `选修` … |
| `KCLBDM` / `KCLBDM_DISPLAY` | string | 课程类别 | |
| `KSLXDM_DISPLAY` | string | 考试类型 | `考查` / `开卷` … |
| **`SFYX`** | string(1) | **是否有效** | **只取 `'1'` 的行**（实测 19/19 全为 `'1'`） |
| `SFJG` / `SFJG_DISPLAY` | string | 是否及格 | |
| `XS` | number | 学时 | |
| `WID` | string(32) | 记录 ID | 幂等键首选 |
| `JXBID` | string(21) | 教学班 ID | |
| `KSSJ` / `SJKSRQ` | string(10) | 考试时间 / 实际开始日期 | |
| `DJCJLXDM` / `DJCJMC` | string/null | 等级成绩类型 / 名称 | 等级制成绩走这里 |

> 其余 `QTCJ1..QTCJ10`（其他成绩，含 `_DISPLAY`）、`BY1..BY10`、`*XS`（成绩系数）等
> 字段本项目不需要；`HASFC` / `SFPJ` / `RZLBDM` / `TSYYDM` 实测为 `null`。

### ★ 学分绩换算的实测验证

拿真实数据对齐了你给的官方 4.3 制表，**完全吻合**：

| 学期成绩 | 学校返回的 `XFJD` | 官方表区间 |
| --- | --- | --- |
| 93 | `4` | 90–95 → 4.0 ✓ |
| 84 | `3.3` | 82–84 → 3.3 ✓ |

**结论：优先直接使用 `XFJD`（`gradePointSource: 'school'`），把官方换算表只作为兜底。**
这样既不用猜测区间边界（例如 95 分归 4.0 还是 4.3），也不会因为换算规则理解偏差算错。


本模块只做成绩，课表相关不在范围内；将来若要补课表，握手部分可直接复用。

## 7. 对模块设计的落地约束

1. `config.js` 需要 `loginUrl` 指向 jwapp 业务 URL（**绝不指向门户页**），
   以及成绩应用的 `appUrl` / `appId` / `gradePath` / `appConfigPath` / `appInitPath` 五个常量。
2. `api.js` 必须实现**四步握手**，并把握手结果缓存（同一会话内不必每次重做；
   换账号或会话失效后要重做）。
3. 响应校验按**字符串 `"0"`** 比对；`401 / 403 / 302-to-CAS / code!=="0"` 要分开翻译：
   - `403` → 「应用授权握手失败」而不是「接口变更」或「无权限」；
   - `401` → 「会话失效，请重新登录」。
4. 只取 `SFYX === '1'` 的行；幂等键优先用 `WID`，退化为 `KCH + XNXQDM`。
5. 学分绩直接用 `XFJD`；官方 4.3 制表只作为缺失时的兜底，并在界面上标明来源。
6. 加权平均分用 `ZCJ`（总评成绩）；等级制成绩（`DJCJMC` 有值）默认不计入，
   在界面上显式提示「N 门成绩形式未识别」。
