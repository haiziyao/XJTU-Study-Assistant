# 教务（ehall / jwxt）成绩接口调研

> 真机侦察记录。**本文件只写路径、字段名与结论，不含任何账号、口令、姓名、学号或真实成绩。**
> 复现方式：`node scripts/ehall-probe.js`（凭据从环境变量读，见该脚本头部注释）。

调研日期：2026 年（本机实测）。上游随时可能改版，**改版时只需要改 `modules/academic/config.js`**。

---

## 1. 登录链路（已实测跑通）

统一身份认证走的是 **CAS OAuth2**，不是思源学堂那种「直接 302 到 `/cas/login`」的经典写法。
拿一个 **jwapp 业务 URL** 进去，会依次跳 4 跳后落到 CAS 登录页：

```
GET  https://ehall.xjtu.edu.cn/jwapp/sys/<app>/modules/<mod>/<action>.do
  302 → https://ehall.xjtu.edu.cn/amp-auth-adapter/login?service=<原 URL>
  302 → https://org.xjtu.edu.cn/openplatform/oauth/authorize?appId=1030&redirectUri=…
  302 → https://login.xjtu.edu.cn/cas/oauth2.0/authorize?response_type=code&client_id=1030&…
  302 → https://login.xjtu.edu.cn/cas/login?service=…%2Fcas%2Foauth2.0%2FcallbackAuthorize…
  200   登录页（含 <input name="execution"> 隐藏域）
```

登录成功后 cookie 落在 `.xjtu.edu.cn` 相关域上（`CASTGC` / `MOD_AMP_AUTH` / `route` / `asessionid` 等）。
`CasAuth`（`modules/lms/cas-auth.js`）那套状态机**可以直接复用**：它支持任意入口 URL，
RSA 加密密码、MFA、图形验证码、重定向链都不用重写。

### ⚠️ 坑一：门户页不能当登录入口

`https://ehall.xjtu.edu.cn/new/index.html?browser=no` 是**纯静态 SPA 外壳**：

| 指标 | 实测值 |
| --- | --- |
| 状态码 / 跳转次数 | `200` / `0` |
| 页面里有没有 `execution` | **没有** |
| `<title>` | 本科教务系统 |

`CasAuth.begin()` 的判定是「没有 `execution` 且最终 URL 不含 `/cas/login` ⇒ 已登录」，
于是它会**误判成「已登录」并跳过登录步骤**，后续所有业务请求再被 302 踢回 CAS。
**结论：`config.loginUrl` 必须指向 jwapp 业务 URL，不能指向门户页。**
（`origin/calendar` 上那份课表模块的注释里记的正是这条经验，本次独立复现确认。）

### ⚠️ 坑二：两个主机

| 主机 | 角色 |
| --- | --- |
| `ehall.xjtu.edu.cn` | 一站式服务大厅：门户、应用中心、`/jsonp/*` 元数据接口 |
| **`jwxt.xjtu.edu.cn`** | **真正的教务系统**；应用外壳的 `window._JW_INIT_CONFIG.indexLogoUrl` 指向它 |

两边都能打模块接口，但 **`jwxt` 需要先用一次 GET 建立会话，否则返回 `401`**（建立后变 403，见下节）。
`modules/academic/config.js` 因此需要同时保留 `baseUrl` 与 `jwxtBaseUrl` 两个地址。

## 2. 模块接口形态

```
POST /jwapp/sys/<appName>/modules/<moduleName>/<action>.do
Content-Type: application/x-www-form-urlencoded
X-Requested-With: XMLHttpRequest
Referer: <host>/jwapp/sys/<appName>/*default/index.do
```

响应外壳：

```json
{ "code": "0", "datas": { "<key>": { "rows": [ … ] } } }
```

**`code` 是字符串 `"0"`，不是数字 `0`** —— 这是最容易踩的坑（用 `=== 0` 判断会全部失败）。

错误形态的区分（实测）：

| 现象 | 含义 |
| --- | --- |
| `200` + `{"code":"404"}` | 应用可访问，但**动作名不存在** |
| `200` + `{"code":"<其它>"}` | 业务错误（`msg` / `message` 里通常有原因） |
| **`403`** + Resin 错误页 | **应用未授权 / 无该接口权限**（不是路径问题！） |
| `401` | 该主机会话未建立（jwxt 上常见） |
| `302 → /cas/login` | 登录态失效 |

### ⚠️ 坑三：403 的判读

拿三个应用做对照，同一套请求形态：

| 应用 | 实测 | 判读 |
| --- | --- | --- |
| `homeapp`（公共应用） | `200 {"code":"404"}` | 可访问 |
| `kcbcx`（我的课表） | `200 {"code":"404"}` | **已授权** |
| `cjcx`（成绩查询） | **`403`** | **未授权** |

也就是说：**`403` 不能读成「路径写错了」**。排查时必须先用一个已知可用的应用做对照，
否则会在动作名上白试很久。`scripts/ehall-probe.js` 的第 2 步就固化了这个对照实验。

## 5. 当前阻塞与解决办法

**状态：登录链路完全跑通；成绩数据接口被拒（403），原因已定位到账号的应用授权，而不是代码。**

用测试账号实测：

- ✅ CAS 登录成功（`login_form` → `ready`），拿到 ehall 会话
- ✅ `GET /jwapp/sys/cjcx/*default/index.do` 返回 200，外壳里的 `_JW_INIT_CONFIG` 带
  `appname: "cjcx"`、`appId: "4768574631264620"`（说明已登录、应用外壳可加载）
- ✅ 对照应用 `homeapp` / `kcbcx` 返回 200（说明请求形态与路径都对）
- ❌ `POST /jwapp/sys/cjcx/modules/cjcx/<任意动作>.do` → **403**

**解决办法（需要账号本人操作一次）**：

1. 用该账号登录 <https://ehall.xjtu.edu.cn>；
2. 打开「成绩查询 / 成绩中心」应用，按页面提示完成申请 / 开通（`needFlow=true` 表示要走一次流程）；
3. 重新运行 `node scripts/ehall-probe.js` —— 第 2 步的 `cjcx` 应从 `denied` 变成 `missing`（即 403 → 200），
   第 4 步就能试出真正的动作名与 `datas` 结构。

## 7. 对模块设计的影响（已并入方案）

1. `modules/academic/config.js` 需要 **两个主机**：`ehallBaseUrl` 与 `jwxtBaseUrl`；
   `loginUrl` 指向 jwapp 业务 URL（**绝不指向门户页**）。
2. `api.js` 的响应校验必须按 **字符串 `"0"`** 比对，并把 `401 / 403 / 302-to-CAS / code!=="0"` 分开翻译成
   不同错误（403 要提示「应用未授权」而不是「接口变更」）。
3. **必须先 GET 一次 jwxt 建立会话**（或在 `restore()` 里预热），否则首次请求是 401。
4. 打通前所有数据接口都以 mock 驱动测试；真实字段只在权限开通后校正一次。
5. 「应用未授权」应当作为**一等错误态**在 `/academic/status` 与前端里显式呈现，
   而不是笼统报「同步失败」—— 这是最可能卡住真实用户的一步。
