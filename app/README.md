# AI 智学程序 · 后端与测试窗口

> **框架（`src/core`）+ 可插拔功能模块（`src/modules`）** 的结构：内核提供 HTTP/WebSocket、
> JSON 存储、指令系统、AI 接入契约与三栏测试界面；每个功能是一个自包含目录，**新增功能不需要改框架代码**。
>
> 后端 Node.js **零运行时依赖**；前端 Electron 或浏览器均可（**当前窗口仅用于联调测试，正式 UI 由主程序提供**）；
> AI 能力本阶段**只留接口**。

- **要加功能？先看 [模块开发指南.md](docs/模块开发指南.md)**
- 接口契约见 [docs/接口文档.md](docs/接口文档.md)

## 快速开始

```bash
cd app

# 1) 只跑后端（接口联调推荐，零运行时依赖）
npm run start:server          # http://127.0.0.1:3210/api/v1
npm run dev:server            # 带 --watch 自动重启

# 2) 跑 Electron 测试窗口（需先装依赖）
npm install                   # electron 为 devDependency
npm run dev:app

# 3) 测试（零依赖；含思源学堂/教务/AI 上游的本地 mock、**单点登录的两个站点联动**、绩点与学分绩口径、视图渲染、农历权威向量、日历/待办/番茄钟端到端测试、局域网直传与**局域网网关**的端到端测试）

```

### 想用 AI 对话？（可选，不配也能跑）

AI 模块（`src/modules/ai/`）兼容任何 OpenAI 协议的端点，默认指向 DeepSeek。**不配密钥时一切照旧**：
`/ai/nl2command` 返回 501，传 `fallback: "rules"` 仍然走本地规则，`/ai/capabilities` 的 `available` 为 `false`。

对话支持：Markdown + **LaTeX 公式排版**（`$…$` / `$$…$$`）、**```svg 绘图**（设置页可开关，
说「画个图」也能临时触发）、以及**默认折叠的操作卡**（日程橙 / 待办紫 / 事件蓝）。

```bash
export PC_AI_API_KEY=sk-…      # 或启动后在「设置 → AI 接入」里填（落 data/ai-config.json，0600）
npm run start:server

curl -s -X POST localhost:3210/api/v1/ai/chat -H 'Content-Type: application/json' \
  -d '{"text":"明天交实验报告，预计两小时"}'
```

**最省事的验证方式**是直接在窗口里说话：中栏输入「明天交实验报告，预计两小时」，
回复会逐字长出来，末尾附一张待办确认卡，点「确认执行」才落库 —— 模型只提议，不直接写数据。

#### 上下文用量与手动压缩（`/com`）

输入框上方那一排控件里有个**小圆环 + 百分比**：它显示"此刻上下文装了多少 / 上限多少"。
点开是一个明细弹层（各分类占了多大 —— 系统提示词 / 工具定义 / 对话消息 / 摘要），
弹层底部有「压缩上下文（/com）」按钮。

- 在输入框里发 `/com`（等价 `/compact`，大小写都行）就是这个按钮：**不会发给模型** ——
  它是给程序看的用户指令，所以不落用户消息、不花 token，直接调
  `POST /api/v1/ai/conversations/:id/compact`，然后在对话流里插一条系统提示条
  （压了几条、摘要多少字、覆盖到第几条；没有可压的就直说"没有可压缩的部分"）。
- **压缩语义**：保留最近 `historyTurns` 轮（默认 12 轮 = 24 条消息）不动，把更早、且还没进过摘要的
  部分并进滚动摘要（摘要常驻系统提示词，所以被压掉的约定不会丢）。待压条数不到 6 条时**不调模型**
  （再点一次也只是重复确认"没得压"，不会再烧一次 token）。
- **上限（分母）**在「设置 → 对话设置 → 上下文上限（token）」里改，默认 1,000,000（1M）；
  它**只影响那个百分比**，不改变窗口截断规则（截断仍然按 `historyTurns` 条数 + 滚动摘要）。
- **数字来源**：圆环的 `used` 优先取**最近一次真实请求的 `prompt_tokens`**（准确且不额外花钱），
  没有真实请求时退化成按字符估算并标注来源；弹层里的分类**永远是估算**（真实 usage 不给分类），
  所以弹层底部会写明"分类为估算，总计来自最近一次真实请求"。接口是
  `GET /api/v1/ai/context?conversationId=`，字段见下。

```bash
# 看某个会话的上下文占用（limit / used / percent / source / breakdown）
curl -s "localhost:3210/api/v1/ai/context?conversationId=<会话 id>"
# 现在压一次（= 在输入框里发 /com）
curl -s -X POST "localhost:3210/api/v1/ai/conversations/<会话 id>/compact"
```

> 注意与 `/ai/usage` 的区别：`/ai/usage` 是**累计花了多少** token（按会话或全库求和，含后台调用）；
> `/ai/context` 问的是**此刻上下文里装了多少**。两个数字用途不同，不要互相替代。

接口清单与「模型只能提议、用户确认才落库」的约定见 [接口文档.md 6.4](docs/接口文档.md)。

### 打开测试窗口的两种方式

**方式 A（推荐，零依赖）：浏览器打开后端托管的测试页面**

```bash
npm run start:server
open http://127.0.0.1:3210/app        # 页面与接口同源，无需额外配置
```

`/app/**` 整目录由后端按前缀托管（带越界防护，且只走白名单 MIME 类型），页面会自动使用同源地址作为 API 基址。
因此**新增前端文件不需要改后端代码**，只要在 `index.html` 里加一行 `<script>` / `<link>`。
访问 `/app`（无尾斜杠）会 302 到 `/app/`：页面内的资源都是相对路径，否则浏览器会以 `/` 为基准解析导致整页无样式无脚本。

**方式 B：Electron 测试窗口**

```bash
npm install
npm run dev:app            # 常规环境（直接 electron .）
npm run dev:app:macos      # 沙箱环境 / 需要 LaunchServices 启动时（见下）
```

`npm run dev:app:macos` 会做三件事：把 Electron 运行时复制到工作区内的 `.electron-bundle/`（首次约 130MB）、
把 `package.json + src` 同步进 `ElectronTest.app/Contents/Resources/app`、写入 `data-dir.txt` 让窗口与项目
**共用同一份数据**（`app/data`），最后用 `open -n` 启动。日志与数据位置会在启动后打印出来。

Electron 的 npm 包只含脚本，真正的二进制默认从 GitHub Releases 下载；若网络不可达会报 `fetch failed`，可指定镜像重试（本机验证可用）：

```bash
ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/ node node_modules/electron/install.js
# 若仍失败，可直接下载解压：https://cdn.npmmirror.com/binaries/electron/<版本>/electron-v<版本>-darwin-arm64.zip
# 解压到 node_modules/electron/dist，并写入 node_modules/electron/path.txt（内容：Electron.app/Contents/MacOS/Electron）
```

> ⚠️ **沙箱环境下的注意事项**（本机 macOS 26 + 宿主沙箱，已逐条验证）：
>
> 1. **直接运行 `electron .` 会崩溃**：进程继承宿主沙箱 profile 后，Electron 在 `ElectronMain` 启动阶段
>    以 `EXC_BREAKPOINT (SIGTRAP)` 退出，且早于应用主脚本执行（最小空白窗口应用同样复现，与本模块代码无关）。
>    **经 LaunchServices（`open`）启动的 app 由 launchd 赋予独立运行环境，可以正常工作** —— 这正是
>    `npm run dev:app:macos` 存在的原因。
> 2. **`open ... --args <未打包应用目录>` 不会加载我们的应用**（主脚本不执行）；必须把应用放进
>    `Electron.app/Contents/Resources/app`，脚本已自动处理。
> 3. 若宿主设置了 `ELECTRON_RUN_AS_NODE=1`，Electron 会被当作普通 Node 运行，
>    表现为 `Cannot read properties of undefined (reading 'handle')`；启动前需 `env -u ELECTRON_RUN_AS_NODE`。
> 4. 应用包**不能放在 `~/Library/Application Support` 等沙箱外路径**（写入会被拒绝），脚本默认放
>    工作区内的 `.electron-bundle/`。

> ⚠️ **Windows + 受限会话的注意事项**（已实测）：
>
> 如果宿主环境限制了 GUI/子进程创建，Electron 会**窗口一闪即逝、进程干净退出**。
> 诊断入口是主进程日志（GUI 启动看不到 stdout，所以刻意落盘）：
>
> ```powershell
> Get-Content data\electron-main.log -Encoding UTF8 -Tail 30
> ```
>
> 典型日志与含义：
>
> | 日志 | 含义 |
> | --- | --- |
> | `!! 子进程退出: type=GPU reason=launch-failed` | Chromium 起不了 GPU 子进程 → 用下面的 `dev:app:safe` |
> | `Cannot read properties of undefined (reading 'handle')` | 宿主设了 `ELECTRON_RUN_AS_NODE=1`，Electron 退化成普通 Node |
> | 停在「测试窗口已创建」之后再无输出 | 窗口被外部关闭；`window-all-closed` 会记一条「窗口已关闭」 |
> | `!! 未捕获异常` / `!! 渲染进程退出` | 真正的崩溃，堆栈会跟在后面 |
>
> 另有两点 Windows 与 macOS 的差异（都已在**测试侧**打补丁，应用代码不变，macOS 行为不受影响）：
>
> | 差异 | 处理 |
> | --- | --- |
> | **POSIX 权限位**：Windows 只认只读位，`0600` 与 `0666` 在 `stat().mode` 上无法区分（实测 0600/0644/0400 → 666/666/444） | `test/ai.test.js` 的 `0600` 断言在 `win32` 上跳过；`secret-store.js` 仍照常按 `0600` 请求，macOS/Linux 照常校验 |
> | **GUI 子进程**：受限会话下 Electron 起不来 | 用 `npm run dev:app:safe` 或浏览器方式（见下）；`scripts/run-electron-macos.sh` 与 `dev:app:macos` 保持原样 |
>
> 规避 GPU 子进程失败（禁用 GPU 与渲染进程沙箱，仅适用于本机联调窗口）：
>
> ```powershell
> npm run dev:app:safe
> ```
>
> **若仍无法启动**：该环境大概率禁止创建 GUI 子进程（`notepad` 同样起不来，事件日志里没有崩溃记录）。
> 这种情况别再折腾 Electron —— 用**浏览器方式**，UI 与功能完全一致，只是没有系统通知：
>
> ```powershell
> npm run start:server
> # 浏览器打开 http://127.0.0.1:3210/app
> ```

主进程刻意使用 CommonJS（`src/main/main.cjs`）：在 ESM 下 `import ... from 'electron'` 会被 Node 解析到
node_modules 里的 npm 包（导出二进制路径字符串），拿不到 `app`/`BrowserWindow`；需要 ESM 模块时用动态 `import()`。

### 待办的分类与父子分级（2026-10）

待办多了两个**自己的**维度（与日程 / 事件的 `category` 分类注册表无关，不要混）：

- **分类 `category`**：自由文本（≤24 字，空串 = 未分类），**不做固定枚举** —— 分类是用户自己的词
  （“期末复习” / “实验室” / “英语六级”）。顶部筛选条「全部 / 未分类 / 各分类」显示条数，
  手机上横向滚动（`GET /todos/categories` 返回 `[{name,total,open}]`，按 total 降序，未分类的 `name` 是空串）。
- **父子 `parentId`**：把一件事拆成几步，父 / 子 / 孙**最多 3 层**。限 3 层的理由：
  每多一层就多一份缩进（手机上 390px 宽，第 4 层的标题只剩几个字），而父子语义也只是“拆几步”，
  再深用户自己也记不住；而且完成父会连带所有后代，层数越深误点的波及面越大。
  服务端对“父不存在（`PARENT_NOT_FOUND`）/ 成环（`PARENT_CYCLE`）/ 超 3 层（`PARENT_TOO_DEEP`）”
  一律 400，dryRun 预览同口径。
- **父完成 → 子自动完成**：`PATCH /todos/:id {completed:true}`（以及 `POST /todos/:id/completed`）
  会把**所有后代**置为已完成，并给被连带的写 `autoCompletedBy: <祖先 id>`；响应带
  `cascaded: { completed:[ids], reverted:[ids] }`，界面按它提示“已连带完成 N 个子任务”。
- **取消完成只回滚“被连带”的那批**：只把 `autoCompletedBy === 该 id` 的后代恢复未完成并清掉标记。
  用户**手动勾过**的子任务不会被回滚 —— 误点父完成再撤销，不能把用户亲手记录的完成态一起抹掉
  （那是数据丢失，不是“恢复原状”）。子任务被手动取消完成时标记也会清掉。
- **子完成不自动完成父**，但父的派生字段 `childCount / childDoneCount / hasChildren` 会跟着变
  （只算直接子级，实时计算、不落库）。
- **删父不删子**：子任务往往是自己独立做完的事，删父级顺手毁掉整棵子树是数据丢失；
  但也不留悬空 `parentId` —— 删除时把直接子级的 `parentId` 置空（**父级已删除，独立显示**），
  响应里 `detachedChildren` 给出被解绑的 id。启动时 `repairHierarchy()` 还会修掉同步合并可能带来的
  悬空 / 成环 / 超层父链（幂等，一条记录都不删）。
- **接口**：`GET /todos?category=<名称|空>&parentId=<id|root>&tree=1`（`tree=1` 返回顶层数组 +
  `children`，`count` 计顶层、`totalCount` / `stats` 计含子项的全部，`limit` 作用在顶层）；
  `GET /todos/categories`；写接口（`POST` / `PATCH`）与 `/commands/execute`（target `todo`）都收 `category` / `parentId`。
- **AI**：`modules/ai/prompt.js` 的待办字段清单与日历模块的 `aiPrompt` 都写明了这两个字段；
  `aiQueryFields.todo` 投影 `category / parentId / childCount / childDoneCount`。给已有待办加子任务必须
  **先 query 拿 id 再 create**（新记录 id 由服务端生成，模型拿不到）；
  `test/calendar-todo-ai.test.js` 用 mock 上游真实跑了一次“一句话拆 3 个子任务”。
- **同步**：同步是“整条记录搬运”（`project()` 只去掉 `createdAt/updatedAt`），新字段天然随行；
  `test/sync.test.js` 断言了 `category / parentId / autoCompletedBy` 出现在 push body 里。
- **取舍（如实记）**：
  - **传输（transfer）模块的待办导入投影没带 `category/parentId`**（`modules/transfer/catalog.js`
    不在本次改动范围），因此“导出再导入”会丢分类与父子关系；同步不受影响。
  - **`/calendar` 聚合仍把子任务按截止日当独立待办**（它回答“这天有哪些待办到期”，
    子任务确实也是到期项）；日历日 / 周视图里父与子会各自出现一行。

### 思源学堂接入（LMS）

把「思源学堂里有哪些课程、作业什么时候截止、什么时候直播」变成日历里的待办与日程。
参考实现是 [yan-xiaoo/XJTUToolBox](https://github.com/yan-xiaoo/XJTUToolBox) 的 `lms/` + `auth/`（Python），
这里用**零依赖 Node** 重写，并且**只读**学校数据（不代交作业、不改任何学校侧内容）。

在测试窗口左栏点「思源学堂」即可使用：

1. **登录**（在**设置 → 统一身份认证**里做，只做一次）：学号 + 密码。密码用 `/cas/jwt/publicKey` 的 RSA 公钥加密后才发出，**明文密码不出本机**；若学校要求两步验证，会让你发短信验证码并输入；连续失败 3 次会出现图形验证码。登录之后学堂与学业情况**同时**就绪。
2. **课程 / 活动**：登录后自动拉取「我的课程」与每门课的作业、直播、回放、资料，并缓存到本地（断网也能看上次结果）。
3. **同步到日历**：点「预览同步」先看清单（新建 / 更新 / 跳过 / 失效），勾选后再点「同步选中」。
   - 作业 → **待办**（截止日；同一天两端都有明确时刻时才做成时段日程），已在学堂提交的作业直接标成「已完成」；
     活动同步成功后还会**自动**跑一次作业待办桥接（见下文「作业自动变成待办」），不必手动点两次；
   - 直播 → **时段日程**（有真实起止时刻，分类「上课」）；只有日期、没有时刻的直播与回放 → **全天日历事件**；
   - 回放 / 资料默认不导入，可在选项里打开；
   - 每条记录带 `externalId = lms:activity:<活动 ID>`，**重复同步只更新不新增**，而且不会覆盖你手动改过的完成状态与提醒。

同步也可以交给后台自动做：打开「自动同步」后，服务每 30 分钟检查一次，间隔到了就按同一套规则执行
（**只新建与更新，绝不删除**），适合「作业一发布就自动出现在待办里」。默认关闭。

#### 作业自动变成待办（默认开启）

待办页的用途是「哪天要交什么」，所以**作业不需要手动同步**：每次活动同步成功（打开学堂页、
点「刷新活动」、自动同步跑完）都会顺手把作业 upsert 成待办，用户不用点两次。

- 只处理**作业**：直播 / 回放 / 资料 / 在线视频都不进待办；
- 字段：`title = 课程名：作业标题`（没有课程名时只用作业标题）、`deadline = 作业截止日（YYYY-MM-DD）`、
  `description = 来自思源学堂`（有活动链接时追加）、`tags = ['学堂']`、`source = 'import'`、
  `externalId = 'lms:activity:<活动 ID>'`；
- **没有截止日就跳过**（`skipped` 里计数）：不编一个"今天/学期末"的假日期；
- 幂等：同一个 `externalId` 只更新不新增；**不会重置**你手动勾过的 `completed`；
- 学堂里已提交的作业 → 待办标 `completed: true`，但**不删除**（你还要回看要求与分数）；
- 学堂撤掉活动 → **不自动删**待办：那可能是你改过/补过备注的记录，自动删不可撤销；
- 开关在学堂首页「自动同步」卡里，默认开启；关掉只停止后续建/更新，**已有待办全部保留**。

接口：`GET/POST /lms/todos/config`（`{enabled}`）、`POST /lms/todos/sync`（立即同步，可选 `refresh`）。
`/lms/todos/sync` 在未登录 / 上游失败时返回 **200 + 零计数 + `reason`**，且**一条都不写库** ——
让调用方能区分「今天没有作业」与「没登录所以没同步」，而不是收到一个 401 去猜。

票据统一存在 `data/auth-session.json`（权限 `0600`，7 天后失效），**不保存密码**；
旧版的 `data/lms-session.json` 会在首次启动时并入它之后删除。
不登录时仍然可以查看缓存的课程与活动（响应里 `loggedIn: false`），但同步等写操作会返回 401。

### 学业情况查询（教务成绩）

把「我这学期考了多少、学分绩多少」变成程序里能看到、能算、能问的数据。左栏点「**学业**」。

- **按学期一键**：成绩明细按学期分组，每个学期行右侧有**三态勾选框**「整学期计入」（全计入 / 混合 / 全屏蔽，点一下全计入、再点一下全屏蔽）；

- **学情分析**：每次同步后自动生成一段点评（200 字内，只依据真实数据，不会编排名与保研线）；
  **没配 AI 密钥也不失败** —— 退化成确定性统计摘要并标注「本地统计」。改了勾选后旧分析会被标成「已过期」；
- **对话里也能问**：「我学分绩多少」「把选修课都排除掉」「同步一下成绩」都能被本地规则或 AI 处理。

### 课表导入（移动教务 wdkb）

把本科教务系统的课表变成日历里的日程。左栏点「**课表导入**」，三件事全在同一页：

1. **登录与学期**：未登录只显示「请先在 设置 → 统一身份认证 登录」（这里不收密码）；
   已登录显示当前学期 + 前后各 3 个学期的下拉 + 「刷新课表」。
2. **预览与选择**：课程卡片（课程名 / 教师 / 教室 / 星期 / 节次 / 周次），**每门一个勾选框且默认全选**；
   顶部的「导入到第几周」可整体截断（默认该学期最大周次），底部实时显示「将写入 N 条日程」。
3. **已导入**：按课程分组列出（课程名 + N 条 + 周次范围），可逐门「删除」、
   「全部删除」或「重新导入」；删除前二次确认。

- **数据来源只有一处**：`https://ehall.xjtu.edu.cn/jwapp/sys/wdkb` 下的三个接口
  （课表 `xskcb.do`、当前学期 `dqxnxq.do`、起始日 `cxjcs.do`）。全部是 `POST` 表单，
  外壳 `{code:"0",datas}` —— **`code` 是字符串**，用 `=== 0` 判断会全部失败。
- **未登录不会被当成"没有课"**：wdkb 未登录会 302 到 CAS，接口返回 **401 `NOT_LOGGED_IN`**；
  上游异常（500 / 非 JSON / `code!=="0"`）返回 **502 `EHALL_ERROR`** 并带原始路径，不回传上游 HTML。
- **合并**：同一天、同课程名、节次连续、周次相同 → 合并成一条（1-2 + 3-4 → 1-4）；
  教师 / 教室不同仍合并并「 / 」并列；不连续（1-2 与 5-6）保持两条。
- **周次跨段拆多条**：`repeat.until` 只能表达连续区间，所以 `1-8 与 10-16` 写成两条日程。
- **幂等**：`externalId = timetable:<学期>:<课程名>:<星期>:<起-止节>:<周次段哈希>`；
  重复导入只更新不新增，`untilWeek` 调小也只更新 / 清理，不会堆重复。
- **删除安全边界**：只删 `source:'import'` 且 `externalId` 以 `timetable:` 开头的日程，
  手建日程一条都不碰（有测试直接断言手建日程还在）。
- **已知取舍**：节次时刻是学校作息制度、接口不提供，按 11 节冬 / 夏两套表硬编码
  （沿用旧实现 2026-01 真机核对）；跨 9/10 月的下午课段按段首作息写入（`repeat` 只有一个 startTime）；
  起始日优先 `cxjcs.do`，历史学期为空时本地推断并在 `startSource` 如实标注。

### 设置 → 账号登录（公开服务端的账号）

「设置 → 账号登录」这一块用来登录**公开服务端**（`server` 分支那套：一个端口跑多租户宿主 +
账号体系）。它和「统一身份认证」是**两回事**，别混：

| | 统一身份认证（`auth`） | 账号登录（`account`） |
| --- | --- | --- |
| 账号是谁的 | **学校的**（CAS / Keycloak） | **服务端的**（用户名 + 密码） |
| 用来干什么 | 拉课表、拉成绩、拉学堂作业 | 证明"你是这台服务器上的哪个用户" |
| 密码存在哪 | 不存（只留凭据 Cookie） | 服务端存**哈希**；本机只存**会话令牌** |

- **两种连接方式**：
  - **桌面端**：填服务器地址（默认 `http://localhost:8866`，即"本机自己跑的服务端"），
    或填别人给的地址；
  - **服务端版**：页面与 `/auth` **同源**，把模块配置的 `defaultServerUrl` 设成空串即可，
    实现里对空值走相对路径（`serverUrl` 留空 = 同源）。
- **地址怎么写**（三条，都是真机上踩过之后定的）：
  - **带上协议最省事**：公网填 `https://study.xjtuwhy.com`（不带端口就是 443），
    本机开发填 `http://localhost:8866`。不写协议也认：域名默认按 `https://` 试，
    `localhost` / `127.0.0.1` / `[::1]` / 纯 IP 默认按 `http://` 试；首尾空白、
    结尾多余的 `/` 会被去掉，**子路径会保留**（`https://x.com/study` 就是挂在 `/study` 下的部署）；
  - **写 `http://` 的公网服务器会登录失败 —— 不是连不上，是方法被换掉了**：nginx 的
    `return 301 https://…` 会把 POST 跳到 https，而 **301 在 fetch 规范里会把 POST 改写成 GET**，
    于是服务端收到的是一个"取登录页"的 GET（没有用户名密码），面板只能显示"响应看不懂"。
    桥现在自己跟跳转，因此**同一方法、同一 body** 会重发一次，登录照常成功；
  - **跳转只允许跟到同一 host 的 https**（本机/回环地址例外）：登录 body 里是明文密码，
    跟着 `Location` 跑到别的域名等于把密码交给对方 —— 那种跳转会直接报 `REDIRECT_REFUSED` 停下。
    跟完跳转后，**最终地址会被写进 `data/account.json` 并显示在面板上**（"下次就填这个"）。
- **面板里能做的事**：登录、用邀请码注册（用户名 / 密码 / 邀请码）、**测试连接**、
  退出登录。未登录时还能点「测试连接」先确认地址对不对 —— 它会显示**服务器名、版本、归一化后的地址**，
  并明确告诉你「**该服务器上思源学堂不可用**」（服务端版不代持学校账号密码）。
- **错误一律是人话**：`BAD_CREDENTIALS` →「用户名或密码不对」、`INVITE_INVALID` →
  「邀请码无效或已被使用」、`USER_EXISTS` →「这个用户名已经被注册了」、`RATE_LIMITED` →
  「失败次数太多，请等 60 秒再试」、连不上 →「连不上这个服务器：检查地址与端口，确认对方在跑」、
  地址写错 →「服务器地址看起来不对：…（示例：https://study.xjtuwhy.com）」、
  地址能打开但不是本程序 →「这个地址能打开，但它不是「AI 智学」的服务端（缺少 /auth/config）」。
  **上游响应体不会被整段透传**，只按错误码查表，认不出来就给一句通用提示。
- **为什么渲染层不直接 fetch 服务器**：页面在 `http://127.0.0.1:3210`，服务端在
  `http://localhost:8866`，**跨域**；而服务端版**故意不发 CORS 头**（同源部署不需要，
  发了反而拆掉"浏览器读不到跨站响应"这层保护）。会话令牌又是 `HttpOnly` Cookie，
  本来就该只待在 HTTP 层。所以渲染层只调本机后端的 `/account/**`，由**后端持有令牌**
  去跟服务器说话 —— `GET /account` 只回 `{connected, serverUrl, user, loginAt}`，
  **绝不回传 token**（`test/account.test.js` 里有断言）。
- **凭据落在哪**：`data/account.json`，权限 **0600**（`data/` 整个目录已被 `.gitignore` 覆盖）。
  里面是 `{serverUrl, token, user, loginAt}`。令牌等于"登录态"，别把它拷给别人。
- **登录本身不搬数据**：登录**只解决身份**（服务器知道"你是谁"）。把数据搬过去的是
  「多端同步」（`sync` 模块，见下一节）—— 它要你**手动点一次「立即同步」**（或启动时自动一次），
  而且只在你自己同意了同步范围之后才动数据。
- **不给 AI 碰**：本模块**没有** `aiTools` / `aiPrompt` / `aiQueryFields` / `commands`。
  账号是用户自己的事，模型既不查也不改。

```bash
# 后端代登录（渲染层走的就是这几条；serverUrl 可省，省了用上次登录或默认值）
curl -s -X POST localhost:3210/api/v1/account/login \
  -H 'Content-Type: application/json' \
  -d '{"serverUrl":"http://localhost:8866","username":"alice","password":"…"}'

# 当前登录态（注意：**没有 token 字段**）
curl -s localhost:3210/api/v1/account

# 探测服务器（不可达也是 200 + reachable:false，不抛错）
curl -s 'localhost:3210/api/v1/account/probe?serverUrl=http://localhost:8866'

# 退出（服务器连不上也会清掉本地凭据）
curl -s -X POST localhost:3210/api/v1/account/logout -H 'Content-Type: application/json' -d '{}'
```

### 多设备同步（`sync`，order 89）

登录**只解决身份**（服务器知道你是谁）。真正把数据搬过去的是 `sync` 模块：
它让**同一个账号**的多台设备（**桌面 ↔ 服务器 ↔ 手机**）保持一致，入口是

> **设置 → 多端同步 → 「立即同步」**

一句话口径：**同步是双向的，但不会静默丢数据** —— 只要两边对同一条记录的内容不一致，
就**两条都留**并把冲突列出来给你看，绝不"谁后写谁赢"。

#### 同步哪些、不同步哪些

| | 集合 |
| --- | --- |
| **同步** | `notes` 笔记、`todos` 待办、`schedules` 日程、`events` 事件、`memories` 记忆、`pomodoro-sessions` 番茄钟会话账本、`ai-conversations` AI 对话、`ai-messages` AI 消息、`ai-schedules` 定时唤醒，以及（**默认关闭**的）`ai-config` AI 配置与密钥 |
| **不同步** | `academic-*`（成绩 / 学业元信息）、`lms-*`（学堂课程 / 作业 / 元信息）、`ai-usage`（用量账本）、传输日志、`account.json`（账号令牌）、**`pomodoro-state`（运行中的番茄钟临时状态）** |

不同步的原因逐条写清楚，免得被当成"还没做"：

- **成绩**：隐私最重，而且它是教务系统拉下来的**只读投影**，同步它只会污染下一次同步的幂等键；
- **学堂数据**：同样是"从学校拉下来的投影"，而且服务端版根本不提供学堂能力
  （宿主对 `/api/v1/lms/**` 明确回 `403 LMS_DISABLED`）；
- **用量账本**：每台设备各自花掉的 token 是**本机事实**，合并起来只会得到一个谁也解释不通的数字；
- **账号令牌**：它属于"这台设备与那台服务器之间的会话"，复制到别的设备上等于把登录态到处撒；
- **番茄钟运行状态**：当前在专注还是休息、还剩多少秒，是"**这台设备此刻正在发生的事**"。
  同步到另一台设备会让两个界面抢同一个计时器（两边都能暂停/停止，谁算数说不清）；
  已经发生的历史（`pomodoro-sessions`）才同步 —— 换设备后今日/本周统计与周报才对得上。

#### 冲突怎么办：两条都留 + 交给你

| 情况 | 结果 |
| --- | --- |
| 同一条记录、内容一样 | 跳过（**幂等**：重复同步不会多出任何东西） |
| 同一条记录、两边改得不一样 | **两条都留**：本机这条保留原 id，另一条换一个 id 存下来（报告里叫「**重命名**」），并列进「冲突」清单 |
| 不同记录、标题一样 | 两条都留 + 进「疑似重复」清单，由你自己决定删哪条 |
| 离线很久的设备推上来一个旧版本 | 跳过（它只是还没同步到；让它 pull 追上，**不会**把刚删掉的东西"复活"成一份副本） |

报告里的「重命名 N 条」不是失败，也不是丢数据 —— 它就是"两条都留"的落地方式：
**没有任何一方的内容被覆盖**。面板上的数字口径：推了 / 拉了 / 更新 / 跳过 / 重命名 /
删除 / 疑似重复 / 冲突（另有逐条明细与来源设备）。

#### 删除同步的支持范围（如实说）

- **笔记**：✅ 有回收站（软删除）。删除会跟着记录一起同步：A 上删掉，B 的列表里也消失、
  进 B 的回收站；从回收站恢复同理；
- **其余集合**：❌ 不支持。它们都是**硬删除**（记录直接消失），本机无法区分"被删了"与
  "从未同步过"，而"给别的模块发明墓碑字段"会改掉它们的删除语义 —— 口径明确不做。
  后果是：A 上删掉的待办/日程，可能在下一轮同步时从 B 那边"回来"。
  接口 `deleted: {<集合>: [id]}` 仍然接受并处理（对硬删除集合**如实拒绝**并在报告里说明），
  所以未来的手机端如果自己维护了墓碑，语义是完整的。

#### 怎么触发

- **手动**：「立即同步」按钮 → `POST /api/v1/sync/run`（一站式：读本地 → push → pull → 就地合并）；
- **自动**：程序启动后自动同步一次，**失败静默**（没登录 / 连不上 / 令牌过期都在预期内），
  原因记在面板的「上次同步失败」里。

失败时的三条硬保证：

1. **本地零改动**：远端不可达 / 401 / 响应畸形时，pull 的结果先落在内存里**校验**，
   通过之后才逐集合合并落盘 —— 同步失败最多是"没同步上"，不会把本地数据写坏；
2. **逐集合隔离**：某一个集合合并出错只记这一条 error，其余集合照常同步；
3. **令牌不出门**：会话令牌只出现在 `Authorization: Bearer` 头里，不进 URL、不进报告、
   不进状态文件、不进日志（状态接口只回 `{connected, serverUrl, user, loginAt}`）。

#### 敏感数据（AI key / 学堂凭据）：默认不同步，只能在自己的设备上开

| 开关 | 同步什么 | 存在哪 |
| --- | --- | --- |
| ☐ 同步 AI 配置与密钥 | `data/ai-config.json`：接口地址、模型、**API key** | 你自己的服务器（只有你这个账号能读到） |
| ☐ 同步思源学堂账号密码 | `data/auth-session.json`（0600）：**登录后的会话票据** | 同上；**服务端版只存储、不使用**（服务端的每用户实例连学堂模块都不加载） |

- **默认两项都是关的**，而且**只能在非网页客户端（桌面端 / iOS / Android / 局域网里的手机 App）里勾**；
  网页版（服务端版发出来的页面）不显示这两个开关，后端也会拒绝（403）—— 判定是纯函数
  `detectRuntimeKind({hostname, hasSameOriginAuthConfig})`：回环/私有网段 → 原生客户端；
  公网域名 **且**同源 `/auth/config` 可达 → 网页版；探测没做成 → 未知（按原生处理但如实标注）。
- **两边都有值但不一样时不覆盖**：只把"本机为空的字段"填上，字段冲突只报**字段名**
  （绝不回报值），密钥/票据永远不会出现在报告、日志或页面里；
- **没勾的设备不会被写入**：即使服务器上已经有这些数据，pull 也会跳过它们，
  并在报告里列出 `skippedSecrets`（"我没同意，它却把别人的 key 写进我机器"是不允许的）；
- 程序**从不保存密码明文**：学堂密码只在登录那一刻用一次，这里同步的是登录后的会话票据；
  而且这张票据是学堂与教务**共用**的 SSO 凭据（学校统一身份认证就是这样设计的）。

```bash
# 一站式同步（面板上的「立即同步」就是这一条；serverUrl 可省，省了用上次登录的那台）
curl -s -X POST localhost:3210/api/v1/sync/run -H 'Content-Type: application/json' -d '{}'

# 状态：设备身份 + 上次同步时间 + 各集合条数（不含令牌）
curl -s 'localhost:3210/api/v1/sync/status?hostname=127.0.0.1&authConfig=0'

# 敏感数据开关（两项默认都是 false；网页版开会被 403 拒绝）
curl -s 'localhost:3210/api/v1/sync/settings?hostname=127.0.0.1'
curl -s -X POST localhost:3210/api/v1/sync/settings -H 'Content-Type: application/json' \
  -d '{"syncSecrets":{"aiConfig":true},"hostname":"127.0.0.1"}'

# 手机端/另一台设备要用的两条：带 Bearer 直连（服务端版宿主接受 Authorization: Bearer）
curl -s -X POST http://localhost:8866/api/v1/sync/pull -H 'Authorization: Bearer <会话令牌>' \
  -H 'Content-Type: application/json' -d '{"deviceId":"phone-1","since":null}'
curl -s -X POST http://localhost:8866/api/v1/sync/push -H 'Authorization: Bearer <会话令牌>' \
  -H 'Content-Type: application/json' \
  -d '{"deviceId":"phone-1","deviceName":"我的手机","collections":{"notes":[{"id":"n-1","title":"手机上写的"}]},"deleted":{}}'
```

设备身份与账本放在模块私有文件里（权限 **0600**）：`data/sync-state.json`
（`{deviceId, deviceName, lastPullAt, lastPushAt, cursor, syncSecrets, …}`）、
`data/sync-ledger.json`（幂等账本 + 版本索引）。完整设计说明见
[`src/modules/sync/README.md`](src/modules/sync/README.md)。


### 教务处政策语料（`knowledge/dean/`）
把教务处官网 <https://dean.xjtu.edu.cn/> 的公开政策文本抓成本地语料，**进仓库、协作者共用**：

- **规模**：18 个栏目 / **148 篇** / 约 **11.5 万字**（学生事务、规章制度、教学业务三大块 + 校历 / 作息时间 / Q&A / 培养方案）；

- **可复现**：`node scripts/crawl-dean.js` 一条命令重抓并重建索引（串行 + 400ms 间隔 + 失败退避）；

  `--url=<页面>` 打印单页的转换结果（排查"这篇抓歪了"）。抓取器零依赖；
- **有意不抓**：教学通知 / 教学动态这类几天就过期的页面 —— 进了语料只会让模型答出过时结论
  （`test/knowledge.test.js` 里有断言挡着）；
- **给 AI 的用法**：只**按需检索**命中段落 + `url`，**不整篇注入提示词**；
  本版明确不做向量检索（关键词 + 栏目够用，见接口文档 §10 的取舍）。
  怎么更新、字段含义、使用约定见 [`knowledge/dean/README.md`](knowledge/dean/README.md)。

### 图片笔记的本地文字识别（随手拍 → AI 能读到）

随手拍进来的笔记正文是空的，字全在图片里。不做识别的话，AI 只能回答"这篇笔记正文是空的"——
用户拍了张写满字的照片，在模型眼里等于一张白纸。这里用 **macOS 自带的 Vision 框架**
（`VNRecognizeTextRequest`）在**本机**把字读出来，**图片不上传任何地方**，也不引任何 npm 依赖。

**怎么发生**

1. 创建 / 导入带 `image/*` 附件的笔记时，先写入 `ocr: { ok:false, error:'pending' }`（"排队中"），
   HTTP 立刻返回（实测 65ms），识别在**后台串行**跑（Vision 吃 CPU，一次只跑一张）；
2. 识别完成把结果写回该笔记的 `ocr` 字段并照常广播 `notes_changed`：

   ```json
   { "ok": true, "text": "识别出的文字…", "chars": 66, "engine": "macos-vision", "at": "2026-10-13T08:24:09.577Z" }
   ```

   识别失败也是**如实降级**，不抛异常、不影响笔记本身：
   `error` 取 `ocr_unavailable`（本机没有 swiftc，编译不出小工具）/ `no_text`（图里没字）/
   `bad_image`（附件不是图片）/ `timeout`（单张超过 30s）/ `failed`；整条笔记没有图片附件时 `ocr` 为 `null`。
3. AI 侧读得到的：`aiQueryFields.note` 里有 `ocr`，笔记检索文本（`/notes?query=` 与三源检索
   `/search?scope=note`）都包含 `ocr.text`，`notes` 模块的 `aiPrompt` 明确要求
   "有 `ocr.text` 就直接用它回答，**绝不许因为正文为空就说里面没有内容**"；
4. 想重跑（换了图、上次失败、第一次没装编译器）：`POST /api/v1/notes/:id/ocr`，同步等结果返回，笔记不存在 404。

**小工具与缓存**

- Swift 源码随模块走：`src/modules/notes/vision-ocr.swift`（约 80 行，只用 Foundation/AppKit/Vision，
  每行结果以 `{"text","confidence"}` JSON 打到 stdout）；
- 首次使用时用 `swiftc -O` 编译到 **`data/.ocr/vision-ocr`** 并复用（源码改了会自动重编；
  `data/` 本就在 `.gitignore` 里，编译产物不入库）。实测：**首次 45–55s**（冷模块缓存，
  含编译 Foundation/Vision 的 `.swiftmodule`），**之后每次识别 0.5–0.9s**；
- CI 上通常没有 `swiftc`：此时识别一律返回 `ocr_unavailable`，笔记功能照常；单测用注入的假引擎覆盖
  "触发时机 / 写回 / 广播"，真实识别那条用例条件 skip（见 `test/notes-ocr.test.js`）。

**识别不了的（如实说明）**

手写体、竖排文字、表格结构基本读不出来或读成散字；**倾斜拍摄**会明显掉准确率
（实测那张随手拍是斜着拍的麻将截图：`环指点彩派学徒`、`铜之间•三人南`、`53000` 这类横排大字读对了，
竖排/斜排的小字读成了 `留无你号`、`曾无称步` 这种错字），识别置信度普遍偏低。它只解决
"照片上有没有字、大概是什么字"，不能当成精确录入。

两台装了本程序的设备在同一个局域网里，**直接把数据发给对方**：没有中转服务器、没有账号、没有云。
左侧「传输」页（`views/transfer.js`，order 66）做全部操作。

**怎么开**

1. 两台设备都启动本程序（同一局域网，不需要公网）；
2. 接收端：打开左栏「传输」→ 页面上大字显示 **6 位配对码**（进页面即生成，10 分钟有效）→ 把它念给发送端；
3. 发送端：左栏「传输」→「附近设备」里选中对方（或手工填 `IP:8886`）→「发送」→ 填对方配对码 → 勾选要传的集合 → 开传；
4. 两端都能看到进度、结果明细（成功 / 跳过 / 重命名 / 疑似重复）与**传输日志**。

- **配对码**：6 位数字、10 分钟有效、**错 5 次锁 60 秒**；配对成功换 30 分钟有效的 token，后续每个分片都带着它。
  它是"用户在场"的证明 —— 同一局域网里任何人都可能往你设备推数据，所以不做成"输入设备名就能传"。
- **可被发现（默认关）**：打开后每 5 秒往 `255.255.255.255:8886` 广播一次"我在这里"，别人才会在「附近设备」里看到你；
  关着也能主动发给别人（只是自己隐身）。广播被防火墙拦、或两台设备不在同一网段时，**手工填 `IP:8886`** 直接连。
- **端口 8886**：UDP（发现）+ TCP（传数据）共用。主服务仍然只听 `127.0.0.1`，**没有**改成对局域网开放；
  8886 上默认只有 4 条路由：`GET /info`（设备信息，免配对）、`POST /pair {code,device} → {token}`、
  `POST /transfer`（带 token 收 bundle，幂等）、`GET /progress`。
  另外，**只有**在「传输」页打开局域网网关之后，同一个 8886 上才会多出 `/app/**`（前端本体）、
  `/api/**`（反向代理到主服务）与 `/ws`（推送通道）—— 三条都要配对码换来的令牌，关掉开关即刻消失，见下一节。
- **端口被占用怎么办**：页面顶部会明确写「端口 8886 已被占用（可能开了两个实例，或被别的软件占用）」，
  此时主程序一切照常（发现通道若也起不来会一并提示），只是收不到别人的传输。处理方式二选一：
  关掉占用 8886 的进程；或给模块换端口 —— 装配时传 `createServer({ transfer: { port: 8887 } })`
  （当前 `bin/server.js` 与 `src/main/main.cjs` 都只传了 `{ dataDir }`，要换端口需要在那里加这一项；
  **不要**为了让别人连上而改主服务的监听地址）。改端口后两台设备都要填对方的实际端口。

**能传什么**

| 集合 | 发送 | 接收 | 说明 |
| --- | --- | --- | --- |
| 对话 / 消息 | ✅ | ❌ | `ai` 模块只有"新建空会话"，没有写回历史消息的入口；只建空壳会让"传过去了"变成假象，所以接收侧**如实跳过** |
| 记忆 | ✅ | ✅ | `scope+key` 冲突时**不自动取代**：并存第二条（key 加 `_from_<设备>`）并进冲突清单让你选 |
| 笔记 / 待办 / 日程 / 事件 | ✅ | ✅ | 统一走各模块自己的 `create()` |
| 成绩 | ❌ | ❌ | 隐私最重（§8.1），默认且**始终**不参与传输 |

- **合并策略**（每次传输的结果明细里逐条可见）：
  同 `id` 同内容 → 跳过（幂等）；同 `id` 不同内容 → **两条都留**，新来的记 `-from-<设备短id>` 后缀 + `origin`；
  不同 `id` 同名 → 两条都留，进「疑似重复」清单由你逐条"删除本机这条 / 保留"；
  记忆 `scope+key` 冲突 → 不自动取代，并存 + 标记冲突。
- **幂等**：重发同一批数据不会重复写入 —— 判据是"将要写入字段的内容指纹"，
  远端 id ↔ 本地 id 的对应关系记在 `data/transfer-log.json`（重启后依然有效）。
- **写入边界（重要）**：接收侧**只调各模块自己的服务**，绝不直接改别人的 JSON 文件；
  没有写入口的集合上面已列出，一律跳过并如实说明原因。
- **分片**：单批 ≤ 2 MB，超了自动分片（同一 `bundleId` + `chunk.index`）；单条本身就超 2 MB 时独占一批；
  笔记模块自己的正文上限是 20 万字，超过的部分由它截断，**截断会写进结果明细**（不静默）。

**隐私边界（如实说）**

- 只在局域网监听，**不做任何公网暴露**（没有打洞、没有中继、没有云）；
- **内容不加密**：同一局域网内、拿到配对码的设备在配对后能看到你勾选传过去的数据；
- 设备服务器**不回 CORS 头**：网页脚本读不到它的响应（本机页面走 `/api/v1/transfer`，不经 8886）；
- 传输日志（谁、什么时候、传了什么、成功/跳过/重命名各几条）在「传输」页可见，
  并落在 `data/transfer-log.json`（**0600**，仅当前用户可读）。

**命令行/接口速查**（`jq` 只是好看，没有也能跑）

```bash
# 设备信息（免配对，另一台设备配对前先问这个）
curl -s localhost:8886/info | jq

# 配对：code 取对方「传输」页上显示的 6 位
TOKEN=$(curl -s localhost:8886/pair -H 'Content-Type: application/json' \
  -d '{"code":"123456","device":{"id":"dev-b","name":"MacBook","platform":"darwin"}}' | jq -r .token)

# 传一批（省略 chunk 表示只有一批；带 token）
curl -s localhost:8886/transfer -H 'Content-Type: application/json' \
  -H "X-Potato-Transfer-Token: $TOKEN" \
  -d '{"bundleId":"demo-1","schema":1,"from":{"id":"dev-b","name":"MacBook"},"collections":{"notes":[]}}' | jq

# 进度
curl -s "localhost:8886/progress?bundleId=demo-1" -H "X-Potato-Transfer-Token: $TOKEN" | jq

# 本机控制面（页面用的；这些走主服务 3210，不对外）
curl -s localhost:3210/api/v1/transfer/status | jq
curl -s localhost:3210/api/v1/transfer/catalog | jq
curl -s -X POST localhost:3210/api/v1/transfer/send -H 'Content-Type: application/json' \
  -d '{"host":"192.168.1.9","port":8886,"code":"123456","collections":["notes","memories"]}' | jq

# 测试（真起两个实例、真分片、真合并；不发真 UDP 广播）
node --test test/transfer.test.js
```

### 手机/平板在局域网里用这个程序（PWA）

主服务只监听 `127.0.0.1`（**刻意的**安全默认），所以 iPhone 打开 `http://<电脑IP>:3210/app` 一定连不上 ——
回环地址在手机上指向手机自己。要让手机真正用起来，就打开「传输」页里的**局域网网关**。

**怎么开**

1. 电脑端左栏「传输」→ 卡片「手机 / 平板打开本程序」→ 打开开关
   「允许手机/平板在局域网内打开本程序」（**默认关**，且重启程序后仍是关的）；
2. 打开后卡片上列出局域网地址，例如 `http://172.20.10.3:8886/app`（点「复制」）；
3. 手机连**同一个 Wi-Fi**，用 Safari / Chrome 打开这个地址 → 先看到一个「需要一个 6 位配对码」的说明页；
4. 填入「传输」页上那个 6 位配对码（10 分钟有效）→ 进入程序本身，之后 30 分钟内不用再输；
5. 想当 App 用：Safari「分享 → 添加到主屏幕」，桌面上会多一个图标，点开就是全屏页面。

**它到底做了什么**

| 路径 | 行为 |
| --- | --- |
| `GET /app/**` | 由 8886 直接提供 `src/renderer/**`（`/app` → `/app/`；MIME 正确；`Cache-Control: no-store`，前端改了立刻生效）|
| `/api/**` | 反向代理到 `127.0.0.1:<主服务端口>`：方法 / query / 请求体 / 请求头逐项透传，管道流式（大 body 不进内存），响应状态码与头原样回 |
| `/ws` | WebSocket 代理（手写 `upgrade` 转发）：手机上的 AI 流式回复与 `data_changed` 推送靠它，少了它页面能开但数据不动 |
| `GET /app?code=123456` | 用配对码换一张局域网令牌（HttpOnly Cookie `potato_lan`，30 分钟）→ `302` 到 `/app/`，code 不留在地址栏里 |

- **门票就是配对码**：`/app/**`、`/api/**`、`/ws` 全都要令牌。没令牌时 `/api` 回 `401` + 一句人话说明，
  `/app` 回那个说明页（有输入框与提交按钮，不是白屏）。非浏览器客户端也可以走 `X-Potato-Lan-Token` 头。
- **防爆破沿用配对那一套**：错 5 次锁 60 秒，与直传配对**共用同一份实现**（`TransferService.verifyCode`）；
  令牌错/过期**不计入**失败次数（那是过期，不是猜码）。令牌失效后页面会重新要求输码。
- **代理失败有明确形状**：主服务没在跑时回 `502 { ok:false, error:{ code:'GATEWAY_UPSTREAM_DOWN', … } }`，
  不把连接挂死；请求阶段 30 秒上限，响应开始后改成 30 秒**空闲**超时，`text/event-stream` 与 WebSocket 完全豁免
  （AI 长回答不会被超时掐断）。
- **主服务端口不写死**：优先模块配置（`createServer({ transfer: { gateway: { upstreamPort } } })`），
  其次环境变量 `PORT`/`POTATO_API_PORT`，再不行就在**本进程监听的端口**里认（认 `/api/v1/health` 的签名）——
  Electron 在 3210 被占用时会依次试 3211…，这一步保证手机连到的是"这一台"，不是别的实例。
- **谁能进、怎么踢**：同一局域网里拿到配对码的人。页面显示"已授权几台设备"，「全部注销」一键踢掉所有手机；
  关掉网关开关，入口**立刻**消失（8886 上不再有 `/app`、`/api`、`/ws`，已发出的令牌一并作废）。

**安全边界（如实说，别把网关当加密通道）**

- 只在局域网监听，不做任何公网暴露（没有打洞、没有中继、没有云），也**没有 HTTPS**：
  自签证书在手机上只会更难用，所以这里选择"说清楚"，而不是假装安全；
- **拿到配对码 = 拿到门票**：进去之后**成绩、笔记、对话都能看到**（网关是"把本机页面给手机看"，
  不是"只允许传文件"）——这也是它与「局域网直传」最大的区别，别把两者的风险当同一件事；
- 因此：**公共 Wi-Fi（咖啡厅 / 酒店 / 学校开放网络）下不建议打开**；用完就关掉，或至少点「全部注销」；
- 手机上目前**没有离线能力**（没有 manifest / service worker）：断网就打不开，"添加到主屏幕"只是个快捷入口；
  真要离线，下一步得做 PWA 缓存（见下文「还差的」）。

### 手机 / 平板上的界面：窄屏是两栏，不是三栏挤一挤

上一节解决的是"**手机怎么连上**"，这一节说的是"**连上之后看到什么**"。
手机浏览器打开的就是这一份前端（网关把 `src/renderer/**` 原样发出去），没有第二套页面。

**一句话规则**：**宽屏（> 760px）三栏不变；窄屏（≤ 760px）两栏 = 窄导航 + 一整屏功能页。**

| 屏幕宽度 | 布局 | 说明 |
| --- | --- | --- |
| > 760px（桌面 / 大平板横屏） | 三栏并排：导航 `clamp(80px,10%,128px)` + 对话 + 功能视图 `min(56%,780px)` | **与以前逐像素一致**，本次改动没有碰宽屏任何一条规则 |
| 421–760px（手机横竖屏、小平板竖屏） | 两栏：导航 **60px** + 内容区 `1fr` | 内容区一次只给一屏：默认是聊天框，点导航换成那个模块的整屏 |
| ≤ 420px（320–420px 的老机型 / 分屏） | 同上，只压缩横向留白 | **字号不再往下降**（16px 是下限，宁可折行） |

**为什么窄屏不做成"三栏挤一挤"**：桌面三栏能成立是因为有 1500px 宽 —— 导航 128 + 对话 + 右侧 780
还能各留出可用宽度。到 390px 上同样三条并排只剩每栏 130px 左右：月视图一格不到 4px、聊天气泡一行两个字、
任何表单控件都点不准。那不是"难看"，是**不能用**，所以窄屏改成一次只给一屏。

**怎么切、怎么退**

| 操作 | 结果 |
| --- | --- |
| 打开 / 刷新 | 停在**聊天屏**（默认）；地址栏会补上 `#chat` |
| 点左栏某个模块（日历 / 学堂 / 笔记 / 传输 / 设置…） | 内容区整体切成那个模块的整屏页面，聊天列隐藏 |
| 点左栏「对话」 | 回到聊天屏 |
| 点功能页顶部的「**← 返回对话**」 | 同样回聊天屏（手机上没有桌面那种"另一栏一直可见"的退路，这条按钮是**唯一的退路**） |
| 手机浏览器后退 / 前进 | 跟着 `location.hash` 在同一屏之间切换 |
| 刷新 / 把链接发给别人 | 停在**同一屏**（`#calendar`、`#settings` …；`?view=<id>` 也认） |

状态只有一处：`state.view`（当前模块）与 `state.mobileScreen`（这一屏给聊天还是给功能页），
由 `shell/app.js` 的 `selectView()` / `setMobileScreen()` 统一写，`location.hash` 只是它的持久化镜像，
没有第二套状态源。DOM 上的表现是两个 body 类：`body.mobile-chat` / `body.mobile-panel` +
`body[data-screen]`，显隐全部由 CSS 决定（**没有任何行内样式**，CSP `style-src 'self'` 友好）。

**字号与点按尺寸（手机档）**

| 元素 | 桌面 | 手机 |
| --- | --- | --- |
| 正文 / 聊天气泡 / 富文本 | 13px | **16px** |
| 输入框 / 下拉 / 文本域 | 12–13px | **16px**（低于 16px 时 iOS Safari 聚焦会**自动放大整页**） |
| 导航标签 | 11px | **12px** |
| 面板标题 / 卡片标题 | 14px | 16–17px |
| 聊天气泡最大宽度 | 92% | **100%**（390px 上 92% 只有 340px，一句话被切好几行） |
| 导航项 / 按钮 / 开关 / 分段页签 高度 | 28–36px | **≥ 44px** |
| 消息间距 | 10px | 14px |

字号下限不是逐个视图去改 CSS，而是外壳层的**一条通用规则**
（`shell/shell.css` 末尾 `@media (max-width: 760px)` 里的 `.view-content / .settings / .chat` 选择器组）：
所有视图的正文一律抬到 16px，只留一张**很短的例外表**（导航标签 12px、月视图格子里的农历/条数 12px、
仪表盘读数 15px、附属说明 13px —— 每一条都写了理由）。
这样新增视图自动满足下限，不需要作者记得"手机上要放大"。

**手机上仍然会遇到的坑（如实说）**

- **iOS Safari 的 `100vh`**：地址栏收起/展开时 `vh` 不变，底部输入区会被盖住。这里用的是
  `height: 100dvh`（前面留一行 `100vh` 给不认 `dvh` 的老内核兜底），所以地址栏动的时候布局会跟着变；
  但 `dvh` 在旧版 iOS（< 15.4）不生效，那时会退化成"输入区可能被地址栏压住一点"。
- **软键盘弹出**：`position: fixed` 的元素在 iOS 上不会跟着键盘上移，Android 的 `visualViewport`
  又各家不同。目前**没有做**键盘补偿 —— 聊天屏的输入区在文档流里（不是 fixed），
  所以键盘弹出时它会被顶到可见区底部，正常可用；但如果你在**弹层（`.modal`）里的输入框**
  打字，弹层可能被键盘遮住下半部分，需要手动往上滚。这是本次**未处理**的一项。
- **安全区（刘海 / Home Indicator）**：`index.html` 的 viewport 带 `viewport-fit=cover`，
  底部输入区与弹层底部都加了 `env(safe-area-inset-bottom)`；桌面 Electron 窗口里 `env()` 恒为 0，
  不影响任何像素。
- **横屏手机**（例如 844×390）：宽度 844 > 760，于是走**三栏**。横屏手机其实更适合两栏，
  本次没做"按高度判定"的分支（会引入第二套断点，收益不明确）。
- **平板中间档（761–1100px）**：仍然是三栏，右侧视图最窄约 430px。这一段没有专门调优。
- **极窄 320px**：导航标签会折成两行（「思源学堂」→ 两行），字号**保持 12px 不缩**；
  功能页内容正常折行，不横向溢出。
- **`location.hash` 与网关配对码**：hash 只在前端，不会发给服务器，所以 `#settings` 这类
  链接不影响 8886 的令牌校验。

装配流程（`src/server/index.js`，**新增功能不用改这个文件**）：

1. `loadModules()` 扫描 `src/modules/<id>/module.js`，按 `order` 排序
2. 建 `JsonStore`（框架集合 + 各模块声明的集合）
3. 逐模块 `createServices`（order 小的先建，后面的模块能拿到前面的服务）
4. 逐模块 `restore`（listen 之前；单个失败降级继续，不拖垮启动）
5. 注册框架路由 + 各模块 `registerRoutes`
6. `listen` 成功后逐模块 `start`；`close` 时**逆序** `stop`

主进程会在同进程内启动后端（端口被占用时自动递增），并通过 IPC 把实际地址与主题令牌交给渲染层；
渲染层不接触 Node API（`contextIsolation: true`、`nodeIntegration: false`）。

## 设计要点

> **框架与功能分离**（最重要的一条结构约定）：`src/core` 只认识「模块描述符」，功能全部在
> `src/modules/<id>/`；后端装配靠目录扫描（新增模块零公共改动），跨模块依赖靠 `order` 表达；
> 前端导航靠视图注册表 `PCModules`。因此**两个人各加一个功能时不会改到同一个文件**。
> 详见 [模块开发指南.md](docs/模块开发指南.md)。

1. **三件事各归其位**：`Event` 管日期/区间（假期、考试周、截止日），`Schedule` 管**时段**（上课、会议、自习，`startTime` 必填、没有完成态），`Todo` 管**截止日 + 完成态**（作业、报名、打卡，独立集合 `/todos`）。日程与待办是两种东西：日程不可「完成」，待办不占时间轴。
2. **指令与 AI 同构**：本地规则解析器与未来的大模型产出**同一种指令对象**（`action / target / fields / filters / confidence / warnings`），落库逻辑只写一遍。
3. **AI 只负责理解**：provider 返回 draft，不直接写库；校验与业务规则仍在服务层，避免模型产出脏数据。
4. **数据安全**：写入走临时文件 + rename；单文件损坏先备份再启动，不做静默清空（修正 PotatoCalendar 的数据丢失级缺陷）。
5. **顺延可追溯**：顺延引入 `rolled` 状态与 `rolledFrom / rolledTo` 双向引用，不再把「被顺延」当作「已完成」。
6. **结构化重复**：支持间隔、星期集合、结束条件（日期/次数），并修正「31 号在 2 月消失」等问题。
7. **零依赖后端**：只用 Node 内置模块，测试与联调不依赖网络安装；Electron 仅作为可选的前端壳。
8. **外部系统只读接入**：思源学堂走「登录 → 拉取 → 预览 → 应用」四步，写库前一定先给用户看清单；每条记录带 `externalId`，重复同步只更新不新增，且不会回滚用户手改的状态。
9. **与 dschat 2 平滑对接**：`/compat/dschat/*` 兼容其 snake_case 字段与按标题删除；`/commands/markup` 直接吃它那套中文标记行；反向可导出 ICS。映射与差异见 [接口文档.md](接口文档.md) 第 8 节。
10. **农历不靠猜**：查表法（1900–2100）按标准编码读（闰月在低 4 位），并**逐日比对 1901–2099 全部 72684 天**、对齐两个独立实现（表驱动的 `zhdate` + 天文算法的寿星天文历 `sxtwl`），顺带修掉常用表里 2097 的错处；向量写进测试，改表就会红。

## 与 dschat 2 的关系（一句话版）

`dschat 2`（同工作区）是「轻量单日事件」模型：无跨天、无状态、无提醒、重复规则较弱，AI 侧靠中文标记行而非 tool schema。
本模块是更完整的日历 + 日程引擎，并**兼容**它的字段与标记行，因此可作为其日历后端的替代或补充。

## AI 接入还差什么

> 一句话现状：**provider 已经接上了（`modules/ai/`），密钥一配就能对话**；
> 没配密钥时行为与以前一致 —— `/ai/nl2command` 返回 `501 AI_UNAVAILABLE`，
> 传 `fallback: "rules"` 走本地规则，界面右上角显示「AI 未接入」。
> 补齐不需要改 `src/core`：`services.aiBridge` 已在全局服务表里，新模块能直接拿到。
>
> 模型要建**待办/日程**时的调用姿势（选哪个集合、哪些字段必填、五个常见错误写法）在
> [接口文档.md 的「★ AI 速查」](docs/接口文档.md) 里；同一套判定表也被写进了系统提示词
> （`modules/ai/prompt.js`），并有测试守着文档与工具清单不漂移。

### DeepSeek 官方 Search / Fetch：一次请求拿全，抓取路径永远兜底

2026-10 接入 DeepSeek 官方检索接口（`POST {searchApiBase}/v1/tools/search` 与 `/v1/tools/fetch`，
Bearer 鉴权）。**默认 `searchProvider: 'auto'`：只要「AI 接入」里配了 DeepSeek API key 就走官方，
没 key / 欠费 / 限流 / 代理不可达时自动降级到原来的结果页抓取**（抓取路径一行没删）。

- **计费与 QPS**：Search 与 Fetch 各 **5 元/1000 次成功请求**（Search 需 200 且 results 非空、
  Fetch 需返回正文；失败/空结果不计费），QPS 各 **5（账号粒度）**。
  `count` 只影响条数、不影响价格，所以 **一次 `search + need_content:true` 拿 N 条全文
  远便宜于 `search + 逐页 Fetch N 次`**（1 次 vs 1+N 次）—— 这就是 `searchNeedContent` 默认 true、
  且正文已带回时**不再逐页 Fetch** 的原因。
- **配置**（设置 → 对话设置）：`searchProvider` 新增 `deepseek` 与 `auto`；
  `searchApiBase`（默认 `https://api.deepseek.com`，可指向自建代理）；
  `searchNeedContent`（默认 true，关掉就不取全文、也不逐页 Fetch）。
  DeepSeek 官方通道默认复用「AI 接入」的 `apiKey`（同一账号、同一份账单），
  只有显式选 `deepseek` 时 `searchApiKey` 才会覆盖它。
- **字段**：官方结果归一化后额外保留 `rerankScore`（0–3，≥1.5 优质）、`authority`（0–4，≥3 高权威）、
  `summary`（600–800 字长摘要）、`date`（RFC3339，同时映射成 `publishedAt: YYYY-MM-DD`）、
  `siteName`、`content`（need_content 的全文）。排序：**`rerank_score` 降序 → `authority` 降序 →
  `date` 新者优先**；没有这些字段的抓取结果仍按原来的关键词相关度排。`notes` 会如实写
  "优质 N 条 / 高权威 N 条"。
- **campus 档**：有 key 时先用官方 `site:` 语法（认得出站点就收窄到该站，例如
  `来访 交流 site:sae.xjtu.edu.cn`；认不出就 `site:xjtu.edu.cn`；多站用 `OR` 连接），
  命中标 `matchedBy: 'site'`。**`site:` 返回空/失败时才回退**到原来的「站内直搜 / 栏目列表直读 /
  公共结果页」，两条本地通道原样保留。有 key 时 `ori_question` 传用户原话（不是模型改写的检索词）。
- **正文**：`readPages` 的顺序变成 **Search 已带 content → DeepSeek Fetch（Markdown）→ 本地容器提取**。
  `via` 新增 `deepseek-content` / `deepseek-fetch`（与 `container` / `body` / `meta-description` 并列），
  `note` 如实说明"官方抽取"还是"Fetch 失败后回退本地"。Fetch 的 403/404 不重试、直接回退；
  408/429/5xx 才指数退避（最多 2 次、总时长 ≤5s）。
- **错误码**：401 → `SEARCH_KEY_INVALID`；**402 → `SEARCH_BALANCE_EXHAUSTED`
  （"DeepSeek 账户余额不足，搜索接口不可用"，不重试）**；429 → `SEARCH_RATE_LIMITED`（可重试）；
  4xx（除 408/429）不重试，5xx 可重试。设置页"试一下"会直接显示后端、错误码与每条的
  `rerank_score` / `authority` / `date` / 正文来源。
- **诚实边界**：`localization`（本地化结果用的 IP）没有传 —— 官方会按服务端出口位置判断；
  官方通道与抓取通道的 `matchedBy` 语义保持一致；官方不可用时结果可能更少更糙，`notes` 会写明原因。

### 联网检索（`web_search`）：校内直搜优先 + 按相关度选引擎

- **校内（`mode: 'campus'`）走四条通道，顺序就是优先级**：⓪ **栏目列表直读**（`readSiteNews`，
  见下一节）；① **直接打校内站点自己的检索接口**
  （博达 VSB 站群：POST `lucenenewssearchkey=base64(UTF-8)` + `_lucenesearchtype=1&searchScope=0`，
  字段名/搜索页路径逐站不同）—— 命中的必然是校方页面；② 公共结果页（`site:` + 校名）兜覆盖；
  ③ 把公网里提到本校的并入。结果排序 `matchedBy`：`column` > `site` > `domain` > `mention` > `web`，
  每条都标明"它是怎么被认出来的"。**为什么先站内直搜**：免密钥通道下 `site:xjtu.edu.cn`
  拦不住别校的教务处（实测返回的是北大/北航的页面），只有站点自己的检索结果才必然是校内的东西。
- 2026-10-13 真网实测**可直搜 12 个站点**：教务处 / 研究生院 / 学校门户（覆盖整个 `*.xjtu.edu.cn`）/
  航天航空学院 / 数学与统计学院 / 新闻网 / 彭康·文治·宗濂·南洋·励志书院 / 钱学森学院；
  查「转专业」共 **169 条**、总耗时 **1.3s**（站点级并发 3）。**打不通或没有检索入口**的 7 个
  （图书馆、钱学森书院、软件学院、电信学部、崇实书院、思源学堂、师生服务大厅）留在
  `CAMPUS_SITE_SEARCH` 表里标 `working: false` + 原因，运行时不会去请求。
- **校外（`mode: 'web'`）免密钥通道按 搜狗 → 360 → Bing → 百度 试，但不赌第一个**：
  每个引擎解析完都算一遍"查询词在标题/摘要里的覆盖率"（标题命中算满分、只在摘要里命中打 6 折），
  **≥ 0.5 就采用**、< 0.5 就换下一个（最多 3 个；三个都空才允许再补一个"最后一搏"），
  覆盖率 0 的单条结果直接丢。阈值与每个引擎的相关度都写进 `notes`，模型据此如实解释"为什么没搜准"。
  实测（2026-10-13）：同一条网络下 **Bing 对中文查询给的是降级结果**（「西安 天气预报 今天」返回
  西安市_百度百科 / 西安旅游攻略 / 西安市政府，一条天气都没有），而搜狗/360 是对的 —— 所以默认
  不再从 Bing 开始；**搜狗被打多了会跳到 `/antispider` 回 403**（约 6 次请求后触发），必须有这条兜底链。
- 请求头按浏览器来（UA / `Accept-Language: zh-CN` / 跳转链带来源站 `Referer`），
  **不带 Cookie、不伪造登录态**。诚实说明：`baike.baidu.com`、`zhuanlan.zhihu.com` 实测**依然 403**
  （裸头与浏览器头一样，是出口 IP 的风控，不是请求头能解决的）。
- **正文抓取有三种来源**（`web-search.js` 的 `extractPage()`），优先级：① **站内正文容器**
  `#vsb_content` / `.v_news_content`（`textSource: 'container'`）→ ② **整页清洗**（`'body'`）→
  ③ **`<meta name="description">` 摘要兜底**（`'meta-description'`）。前两种是**真正文**；
  摘要兜底只在清洗后不到 200 字时启用，**且一定带 `note` 说明"这是摘要，不是正文全文"**。
  2026-10-13 真网实测：`sae.xjtu.edu.cn/info/1024/1173.htm` 由"865 字全是导航"变为
  **688 字正文**（汤铁钢 / 申胜平 / 徐自力等人名都在）—— 根因是清洗时 `form` 被**连内容整块丢掉**，
  而 VSB 把整篇文章包在 `<form name="_newscontent_fromname">` 里，**不是"JS 之后才加载正文"**。
  页面里那个 `content.jsp` 是**浏览量计数器**（`counter.js` 用 `new Image()` 打点）：
  按 VSB9 形状请求它**返回整页 HTML 而非正文片段**，所以没有实现站内接口通道。
- **摘要必须标来源**：`via` / `note` 一路透传成模型侧的 `textSource` / `note`
  （`chat-service.js` 的 `web: […]` 投影表）。**为什么**：模型看不到"我们是怎么抓的"，
  不给来源它就分不清"读完了全文"和"只看到两百字摘要"，于是会拿摘要承诺细节
  （"会上确定了三项合作"）。`textSource: 'meta-description'` 就是在告诉它"这条只看到标题与摘要"。
- **抓不到正文的页面类型（如实说）**：完全靠 JS 渲染的（正文只有接口返回、HTML 里没有）、
  要登录的（成绩 / 作业 / 课表那类，我们不带 Cookie 也不伪造登录态）、正文在图片或 PDF 里的、
  以及把正文放在 `frameset` / `<iframe>` 里的（我们只读顶层 HTML，不跟进子框架）。

### 校内栏目列表直读（`readSiteNews`）：让"最近有什么新闻"真的读到最新几条

真机反馈（2026-10-13）逼出来的功能：用户问「最近我们航天学院有什么新闻吗」，AI 连着搜了两轮，
如实回答"学院官网的新闻列表页似乎没被检索到，命中的多是 `/info/1035/`、`/info/1093/` 这类**招生栏目**"
"能搜到的学院新闻只到 2026 年 1 月两条"。**不是模型不会搜，而是通道用错了** ——
`searchCampusSites` 走的是各站点自己的检索接口，而 VSB 站群的新闻/通知**列表页经常没被站内搜索收录、
或索引明显滞后**；而 `sae.xjtu.edu.cn/index/zhxw.htm` 上明明白白列着 2026-10-10 的学院新闻。

- **做法**：问法像"最近/最新/新闻/通知/讲座"这类**要最新列表**的问法、又能从检索词里**认出目标站点**
  （`findCampusSiteForQuery` 用 `label` + `aliases` + `host` 取最长命中；认不出就**不读**，免得读错站）时，
  与站内直搜**并行**去读该站的栏目列表页，取**按发布日期倒序**的前 10 条
  （`matchedBy: 'column'` + `publishedAt` + `site`）。栏目条目**不再抓正文**：列表页已经给了
  标题+链接+日期，够回答"最近有什么"；要读某一篇，模型用 `fields.url` 直读那一条（已有能力）。
- **栏目页不硬编码**：优先从首页锚文本（新闻/要闻/动态/通知/公告/学术/讲座…）里现找，
  再补 `CAMPUS_SITE_SEARCH[i].columns`（逐条实测过的兜底清单，最多 3 个）与通用兜底路径；
  并发 4、单页超时 8s、**单个页面失败完全隔离**（`fetched[]` 逐页写 `ok/count/rows/dated/error`）。
  **`columns` 之所以要排在首页之前**：首页链接是按导航顺序排的，主新闻栏目常排在若干个
  "工作动态/团委动态/工会动态"之后，只按首页顺序取前 5 个会把"综合新闻"挤掉（sae 实测就是这样）。
- **日期解析**覆盖 `2026-06-20` / `2026/06/20` / `2026.06.20` / `2026年6月20日` / `[2026-06-20]` /
  `2026.06`（只到月，**不补 01**）/ `06-20`（年份在相邻元素里）。**优先读带 `date`/`time` 类名的
  日期块**，读不到才扫整行 —— 真网踩过两次：会议通知的摘要里写着"本次会议将于 2026年11月2日举行"、
  书院新闻的摘要开头是"2026年10月7日下午…"，扫整行抽出来的是**事情发生的日子**，不是**发布的日子**。
- **跨域条目一律丢掉**（同 `searchCampusSites` 口径）：导航条、友情链接、合作单位常跟新闻列表同页，
  放松域名就等于让别校的通知混进"校内最新通知"里 —— 那不是"不够精确"，那是假的。
  **抽不到发布日期的行也一律不当条目**（导航链没有日期），整页 JS 渲染时**返回空 + 每页原因**，
  绝不把标题硬塞成新闻。
- **排序**：`column` 是最高档；并且在"新闻类查询"里栏目条目**直接给满分相关**，
  这样 `Array#sort` 的稳定性能把 `readSiteNews` 的**日期倒序原样保住**（同分不重排），
  模型看到的顺序就是时间顺序。**为什么必须给它满分**：按关键词覆盖率算，栏目标题里往往没有"最近"，
  而招生栏目标题里恰好有"转专业"这种查询词 —— "最新新闻"会输给"招生通知"，正是真机上的那种错位。

### 对话运行时：中途停止 / 过程清单 / 检索预算 / 消息排队

> 这一节讲的是"一次提问从发出到收尾"这条链上的四件事：**①②③④ 在 `modules/ai/` 里**（服务端契约），
> **⑤ 是渲染层怎么消费这些契约**（`shell/app.js` / `shell.css` / `index.html`）。
> 没有改 `src/core`、没有加运行时依赖。服务端端到端测试见 [test/ai-runtime.test.js](test/ai-runtime.test.js)（8 个用例，零真实外网），
> 渲染层行为测试见 [test/renderer-chat.test.js](test/renderer-chat.test.js)（9 个用例：真 DOM 断言 + 可控 fetch）。

**① 中途停止（`POST /ai/chat/stop`）**

```bash
curl -sX POST localhost:3210/api/v1/ai/chat/stop -H 'Content-Type: application/json' \
  -d '{"conversationId":"<会话 id>"}'
# 确实打断了一次在跑的回合：
{"ok":true,"stopped":true,"conversationId":"…","messageId":"…"}
# 当前没有在跑的回合（**不是错误**，重复点停止、消息刚好答完都会走到这里）：
{"ok":true,"stopped":false,"reason":"idle"}
```

- 同时通过既有 WebSocket 广播 `{"type":"chat_stopped","payload":{"conversationId":"…","messageId":"…"}}`；
- 被中断的那条 assistant 消息**落库**为 `status:"stopped"`，`content` 是**停止前已生成的部分**，
  另有 `stoppedAt`。它**不会**被当成正常答完（`done`）—— 界面据此显示「已停止」而不是红色错误；
- 打断的范围：正在流式输出的上游调用（`provider.chat` 的 `AbortSignal` **覆盖到读响应体为止**，
  见 `provider.js` 里那段注释）、正在跑的写操作循环、正在搜的检索（搜到一半就"不再等它"，
  底层请求自己在后台结束、结果丢弃）；
- `stop` 只作用于**正在跑**的那一轮。已经排队的消息会在它之后继续跑 —— 界面侧的排队是**本地**的
  （见 ⑤）：点停止只停当前这一轮，队列照发；想"连队列一起丢"就在排队条上点 × 或切换会话（会自动清空并提示）。

**② 过程清单（AI 的 todolist，WS `plan` 事件）**

```json
{"type":"plan","payload":{"conversationId":"…","messageId":"…","steps":[
  {"id":"q1","label":"检索「西安 天气」","status":"running","target":"web"},
  {"id":"w1","label":"写入日程「项目周会」","status":"pending","target":"schedule"}
]}}
```

- 步骤**只从这一轮模型发出的草稿里**来（只读查询 → 「检索/查询 …」，写入 → 「写入/修改/删除 …」）；
- `status` 依次走 `pending → running → done | failed`；**每次都是全量快照**（`steps` 整份重发），
  前端整体重画即可，不用做增量合并；
- 同一回合内 `messageId` 不变（所有轮次的步骤都挂在这一条 assistant 消息上）；
- 收尾（正常答完或停止）会再广播最后一份：正常收尾全部 `done`（等用户确认的写操作也算"系统这步做完了"），
  被停止时没跑完的落成 `failed`（它确实没完成，标 done 就是撒谎）；
- **纯聊天一条 plan 都不发**：给"你好"套一层进度条会让用户以为系统在背后做了一堆事。

**③ 检索重试预算（`searchRetryMax`）**

- 新配置项：**默认 3、范围 1–6**，进白名单 / `GET /ai/config` / `/ai/status` / 环境变量 `PC_AI_SEARCH_RETRY_MAX`；
- **一个回合内**按"联网出网次数"计（搜索一次算一次，`fields.url` 直读也算一次；
  参数不全、联网关着不算 —— 根本没出网）；
- 每次 web 查询的结果里带 `attempt`（第几次）与 `remaining`（还剩几次），
  并且**在回灌文案里写清**「本次检索是第 N 次，还剩 M 次」；
- 失败或没有可用结果（`count === 0` / 全部 `ok:false`）时，回灌里给三条**具体**建议：
  ①换更短更具体的关键词 ②直接读某个校方栏目的网址（`fields.url`）③确实拿不到就如实说 + 给下一步；
- 预算用尽：**不再执行新的 web 查询**，把 `error.code = "SEARCH_RETRY_EXHAUSTED"` 当结果回灌给模型收尾
  （不静默丢弃 —— 静默跳过它只会照着"我搜过了"继续编）。此时回灌里**只给第 ③ 条**建议：
  ①②（再搜一次 / 直读某个网址）此刻已经做不到，劝它去做只会多一条被挡回来的草稿。

**④ 消息排队（服务端这一半：同一个会话串行）**

`send()` 里有一把**会话级**的排队锁（`#acquireTurn`）：同一个 `conversationId` 同一时刻只跑一轮，
后到的请求按到达顺序等前一轮收尾（HTTP 请求就挂着，轮到了才开始跑）；**不同会话互不影响**。

- 为什么必须串行：两轮并行会出现"两个气泡同时在长"、而且后一轮组装上下文时会把前一轮刚落的
  用户消息也读进去 —— 等于抢答了下一句；
- 界面按"已发出、还没收到回复"的消息数显示"排队中"即可，**没有**额外的排队事件（有意不加：
  排队是纯等待，界面自己就知道自己发了几条）。

**⑤ 渲染层：排队条 / 停止按钮 / 清单卡（`shell/app.js`）**

服务端那几条契约（stop 的两种返回、plan 的全量快照、同会话串行）在界面上是这样落地的：

- **"当前这一轮"只有一个事实来源**：`state.round`。排队要不要排、停止按钮亮不亮、
  清单卡什么时候收尾，全都看它 —— 拆成三套判断（"在流式吗"/"按钮亮着吗"/"清单还转圈吗"）
  迟早互相打架，表现成"上一轮明明结束了，下一条却还在排队"这类没法复现的怪状态。
- **排队是内存态**（`state.queue`，`{id,seq,text,files}`）：一轮没答完时再按发送**不打断**它，
  而是入队；回合结束（正常/停止/出错都算）后按到达顺序自动发队首。为什么不直接再发一个请求：
  同会话服务端本来就串行，第二条 HTTP 会一直挂着不返回，屏幕上就同时出现"上一轮还在写 +
  下一轮在转圈"；而且请求一旦发出去就撤不回来。排队把"什么时候发"留在用户手里（chip 上的 ×）。
  上限 **20 条**，到顶只提示不入队（无上限等于把"AI 已经跟不上了"这件事藏起来）。
- **排队条在输入区上方**（`#chat-queue`）：chip = 入队序号 + 前 20 字（鼠标停一下看全文）+
  `×` 取消；两条以上再加一句「N 条排队中」。切换会话（打开历史对话 / 新建对话都算）**清空队列**
  并留一条系统提示「切换会话，已清空 N 条排队消息」—— 队列属于上一个会话，留着会写进旧会话。
- **停止按钮**（`#chat-stop`，方块图标、`title`/`aria-label` = 停止本轮）与发送按钮**同一个位置**：
  一轮在跑时顶替它出现（发出消息后就乐观显示，收到 `ai_delta` 仍显示），在
  `/ai/chat` 响应、`ai_message`、`chat_stopped` 三处隐藏。单独一个按钮而不是把「发送」改造成停止，
  是为了不让两种语义共用一个 click 处理器（迟早会出现"想停止却发出去一条消息"）。
  `stopped:false / idle` **不是错误**：只 toast 一句「当前没有正在进行的回合」。
  首条消息刚发出、界面还没拿到会话 id 时点停止不会静默丢：记下意图，`ai_delta` 一到就补发停止请求。
- **停止后**：气泡保留停止前那半段正文（服务端也这么落库），底部加一个中性小标记「已停止」
  （`::before` 画一个 ■，不是错误卡、不用红色 —— 停止是用户自己的决定）；
  这一轮**不再补画草稿确认卡**（"别弄了"之后又冒出一个待确认的写操作等于没停），
  已经自动执行掉的写操作仍照常回执。队列里的下一条照发。
- **清单卡**：收到 WS `plan` 就在当前 assistant 气泡里**整体重画**一张
  `chat-card op-card plan-card`（位置固定在「思考卡之后、正文之前」——正文永远在最底下）；
  每步 `○ 待处理 / ◐ 进行中 / ✓ 已完成 / ✕ 失败` + 服务端给的整句 label。
  全部 done/failed 后**默认收成一行**（「已完成 N 步」/「已完成 2 步 · 1 步失败」/「2 步失败」），
  点标题可展开明细 —— 一轮跑完会留下好几行步骤，历史消息一多，屏幕上全是清单，
  用户想看的正文反而要滚半天。用户手动开/关过之后就不再自动改（他刚点收起、下一份快照又弹开会以为点不动）。
  纯聊天的空快照、别的会话、别的 messageId 的清单都不画（定时任务那一轮的清单没有对应的气泡可挂）。
- **历史回放**：落库的 assistant 消息里**没有**步骤字段，所以回放的清单卡画不出来
  （按"拿不到就跳过、不要编"处理）；但 `status:"stopped"` + `stoppedAt` 是落库的，
  「已停止」标记在历史消息上照常显示。
- **"切换会话"要处理正在跑的那一轮**：HTTP 请求取消不了，服务端还在为旧会话跑。界面把它记成
  "孤儿回合"（`state.orphan`）：等它回来时，如果用户已经切回那个会话**且此刻没有别的回合在跑**，
  就补画一次；否则不打扰（那条消息下次打开这个对话自然会出现）。迟到的响应也不会再把会话 id
  改回旧的（`round.token` 比对）—— 以前会出现"我明明点开了另一条对话，它自己跳回去了"。
- **设置页**新增「一次提问最多检索几次」（`searchRetryMax`，1–6，紧挨「网络搜索最大条数」）：
  两者是两回事 —— 一个是"一次检索读几个网页"，一个是"一次提问最多发起几次检索"。

**手机上（`@media (max-width: 760px)`）**：排队条换行不横滚、chip 文本收窄到 `40vw`
（长文本省略号截断，不撑破输入区上方那一整条）；停止按钮 48×48（≥44px 的点按下限，
它是"我现在就要它停下"的逃生口）；清单行与「已停止」标记在手机上回到 13px / 12px
—— 那几条 `16px` 下限的规则是给正文用的，套到清单上会把卡片撑得又高又散。

### 还差的（按重要性）

1. **产出的 `source` 没能区分人机**：本地规则解析器写 `"command"`，模型草稿目前也走同一条
   `/commands/execute`，所以同样是 `command`。要在数据上区分「这条是模型加的」，
   可以给草稿打 `fields.source = "ai"` —— 注意这与"用户确认后才落库"并不冲突：
   人确认的是**内容**，不是**来源**。`Event` / `Schedule` 的 `source` 枚举已含 `manual / command / ai / import`。

2. **工具调用循环已经有了，但还不是原生 function calling**：模型依旧用"回复里附一段 ```command 草稿"
   来表达动作（各家 OpenAI 兼容端点对 `tools` / `role:"tool"` 的校验不一致，走文本更稳）。
   区别是现在**最多 5 轮**：每一轮都能发查询草稿，后端执行后把结果回灌、接着问，直到模型不再查新东西或到上限；
   写操作**每一轮**都会被处理（`auto` 档直接落库并出「已自动执行」回执）。
   还没做的：模型不能自己从 `aiTools` 清单里挑"调哪个 HTTP 工具"（那份清单是给外部 Agent 看的），
   也没有失败重试与并行调用。

3. **记忆（Agent 记忆）只有契约**：[接口文档 §10](docs/接口文档.md) 把数据模型、6 个接口、
   注入预算与排序、「AI 推断的记忆一律不能直接写」都定死了，`/ai/context` 的钩子也留好了
   （记忆模块只要暴露 `services.memory.inject` 就自动生效），差的只是一个模块。

4. **没有写入权限边界**：目前任何调用方都能 `POST /commands/execute` 直接落库（本机 Electron 壳下可接受）。
   真要开放 Agent，需要决定「谁能写」以及写操作是否强制先跑 `dryRun` 预览。

## 待办 / 扩展点

> 新建 `src/modules/<id>/` + `src/renderer/views/<id>.js`，不用修改 `src/core` 与外壳。

- **原生 function calling 与更多轮次**：现在是「文本草稿 + 最多 5 轮回灌」的循环（见上），
